- Chat: the repeat guard now starts the counts over after any change not made before in the run, not only after a `write` or `search_replace`: a shell command that writes a file (`echo v1 > a.txt`, `sed -i`, `mkdir`, `git checkout`, `git stash`, `cargo add`, `npm install`, `Set-Content`, `del`), also inside `if`/`then` or a `for … do` loop, a screen action, a helper started or merged, or a message the person sends mid-run. A change made before counts like any call and starts only the other calls' counts over, so the same successful write made three times is refused on the third (before, a write never counted itself), and so is a pair of changes that undo each other in turn or two screen actions that alternate. `cargo test 2>&1 | tail -5` writes no file, so alternating it with `cargo build 2>&1 | tail -5` still refuses the third run of each. A read of a background command or helper that is still running never counts as a repeat, so the read that brings its result is never refused; a read of a task that ended counts like any call. /rewind snapshots also cover PowerShell writers (`Set-Content`, `Remove-Item`, `Clear-Content`, `Tee-Object` and Windows PowerShell 5.1's `del`, `copy`, `move`, `ren` and the rest) in any letter case.
