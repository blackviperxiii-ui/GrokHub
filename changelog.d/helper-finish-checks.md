- Helpers: a helper that ends right after a change no check covered gets one note to check it (for code, run the tests or a build) before it hands back, unless fewer than two steps are left for the check and the reply. That costs one more model call, once per unchecked change: a helper sent on by a SubagentStop hook is not noted again for a change it was already noted on. A test, build or other command that ran to a failing exit code still counts as the check, in a helper and in the chat alike, since its result says how it went; a change it may have made is not assumed. A line that failed before its check could run does not count: a program the shell could not find or read (exit 126, 127 or 9009), or a line of several commands, such as `cd sub && cargo test`, where an earlier one may have failed. Its result now ends with what its own calls did, read from the run rather than its words: `changed:` the files it wrote, `ran:` its commands with how each ended (`exit 0`, `exit 3`; the newest 8), and `unchecked:` any change still not checked, each on one line with secrets and personal details masked as the close check masks them; a long unchecked item is cut in the middle, so a path keeps its file name. When a SubagentStop hook sends the helper on, the rerun goes on from the same record, so a check in it covers the first run's changes. A helper that only read hands back its answer as before.
