- Chat: the stall guard now counts a read or search as progress only when it brings back output the run has not seen. Writes, test and build runs and other work always count. A step whose only calls waited on a task that is still running (a second or more, or bringing new output) counts neither way, until 30 such steps in a row have brought nothing new; then each counts as idle. A wait beside a call that failed or found nothing new doesn't hide that call, and a quicker read that found nothing new is a read like any other. The history being compacted makes every read new again. A run whose steps keep coming back with nothing new gets the change-approach note after 6 such steps and stops after 12, like one whose calls keep failing. Trade-off: grep and glob say `(no matches)` for every miss, so a run that checks for absence with many different searches that all miss stops too; the stop note invites a continue.
