- Security: a `sudo` inside a longer command no longer takes the rest of that command out of the shell sandbox. Only a command that is just the system's `sudo` (or `pkexec`, `doas`, `su`, `run0`) runs outside it, behind its password dialog. A `sudo` in a chain, with something set or wrapped around it (`PATH=… sudo`, `env sudo`, `exec -a sudo`), or run from a path such as `./sudo` stays in the sandbox, and a note says how to run a real raise on its own.
- Security: WebFetch allow and deny rules now read a URL with web fetch's own parse, so they match the host, port and path a fetch really connects to: `https://other.test?.github.com` no longer counts as `github.com`, a port is compared as its number (`:08443` is 8443, no port is 443), and an IPv4 address counts in any spelling (`2130706433` and `0x7f.1` are `127.0.0.1`). Web fetch refuses a host no browser would open (`evil.test]`, `]evil.test`, `evil%2etest`, `1.2.3.4.5`), and a deny rule for `evil.test` still covers `evil.test]` and `evil%2etest`. A deny or ask rule also covers the host when the URL ends in a `?` or `#` part, pads the host with blanks, or uses `http://` (web fetch always connects over https). An allow URL rule that names no port now allows port 443 only; `domain:` rules still cover every port.
- Security: the hard floor now reads each word of a shell command the way the shell reads it, and refuses the command when a word could name a key folder, `/etc/shadow` or `/etc/sudoers`, the app's secrets or pair tokens, the Grok sign-in file, or the consent ledger. It reads quotes, escapes, line continuations, `$"…"` and `$'…'` strings, brace lists and sequences, `${x:-word}`, globs with bash's rules (classes such as `[e]` and `[[:alpha:]]`, and no leading-dot match), an expansion it can't see as a wildcard (`.s${x}sh`), `bash -c` and here-documents, and each folder a `cd` or `pushd` may move to; it also matches globs on disk and follows links, within a small time and file budget. On Windows it also reads PowerShell and cmd: backticks, `%VAR%`, NTFS streams (`secrets.json::$DATA`), trailing dots, 8.3 short names, and drive-root, admin-share and device paths. So `ls ~/.*`, `du -sh ~/.*`, `ls /etc/*`, `cat ../.???/id_rsa`, `cat ~/.config/*/*.json` and `echo x >> ~/.config/*/*.jsonl` are refused like `ls ~/.ssh`. A program that builds a path when it runs (`python3 -c` joining strings) is outside the floor; the shell sandbox hides those folders from it.
- Security: Allow always on a command whose quoted text holds `&&` now covers only that command, never a later chain that reads the same.
- Privacy: the Files scope refuses your home folder, and any folder that holds it, however its path is written (`/home/user/.`, `/home//user`, `C:\users\user`, the trailing dots and blanks Windows drops such as `C:\Users\User.`, `\Users\User` from the drive root, `\\localhost\c$\Users\User`, `\\?\` and `\??\` paths, 8.3 short names such as `C:\Users\ADMINI~1`, macOS's `/System/Volumes/Data/Users/<name>`, and a link to it).
