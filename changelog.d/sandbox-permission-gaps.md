- Security: a `sudo` inside a longer command no longer takes the rest of that command out of the shell sandbox. Only a command that is just the system's `sudo` (or `pkexec`, `doas`, `su`, `run0`) runs outside it, behind its password dialog. A `sudo` in a chain, with something set or wrapped around it (`PATH=… sudo`, `env sudo`, `exec -a sudo`), or run from a path such as `./sudo` stays in the sandbox, and a note says how to run a real raise on its own.
- Security: WebFetch allow and deny rules now match the host a fetch really connects to, so `https://other.test?.github.com` no longer counts as `github.com`, and a deny rule also covers that host when the URL ends in a `?` or `#` part, pads the host with blanks, or uses `http://` (web fetch always connects over https).
- Security: the hard floor now sees key files and the consent ledger through shell quotes, escapes, line continuations, `$"…"` and `$'\u…'` strings, globs (POSIX classes such as `[[:alpha:]]` too), brace lists and sequences, doubled slashes, and a `cd` earlier in the command (`~/."ssh"`, `~/.ss?`, `~/.s{s..s}h`, `/etc//shadow`, `consent.json?`, `cd ~ && cat .*/id_rsa`); on Windows also through PowerShell backticks and trailing dots (`` .s`sh ``, `.ssh.`). A glob after the home folder or `/etc` that could reach a key folder now counts, so `ls ~/.*`, `du -sh ~/.*` and `ls /etc/*` are refused like `ls ~/.ssh`.
- Security: Allow always on a command whose quoted text holds `&&` now covers only that command, never a later chain that reads the same.
- Privacy: the Files scope refuses your home folder however its path is written (`/home/user/.`, `/home//user`, `C:\users\user`, and the trailing dots and blanks Windows drops, `C:\Users\User.`).
