- Auto mode: `git fetch` and `git pull` skip the review only with everyday options written out in full that take no value, and a plain remote, path or https or ssh address with plain branch names. Anything else, such as `--upload-pack`, `-j 4`, `--depth 1`, a shortened option, `--`, a wildcard such as `git fetch *`, a network share such as `//server/share`, or another transport, now goes to the review, and to an approval card when that review blocks it.
- A git command pointed at another folder, such as `git -C vendor/lib log -p` or `env -C vendor/lib git fetch`, no longer runs without a check, since the settings of a repository in that folder can name programs to run. Auto mode now reviews it, and Ask mode shows an approval card. The same goes for a command run through `env` with another program search path (`-P`) or name (`-a`). `git -C .` runs as before.
- `@diff`, `@staged` and `@git:N` no longer run programs that a repository's settings name (external diff tools, text conversion, filters, signature checks), including settings pulled in by `include.path`, the settings of a submodule with changes of its own and a filter added while the diff runs.
- Only the words you type have their `@` references read. One in the main reply quoted into a side question, in a side answer sent on to the main task (also with Focus help on), in a Pulse card's report, in a Workboard card's notes, or in the message Resume sends for a Workboard card or a Code tab session (built from its checkpoint) stays plain text. So does one in text the app puts in the message box for you: a findings card's fix button and Do all, a Pulse card's offer, a card's work prompt, an autocomplete you take with Tab, and a resume block or a told side answer that Stop puts back in the box. The references you type before, after or under that text read, and one that text holds stays text even after you edit the words around it, also when the message goes as a side question or waits behind a reply. A suggestion button under a reply never carries an `@` reference, since tapping it sends words the reply wrote. This holds each time the same message is sent again in its chat: `/retry`, `/retry` after the app restarts, and the send once a model is back. The app keeps which words of such a message you typed, so sending it again reads no more than the first send did. A word-for-word copy of such a message, typed or pasted into an empty box, stays the app's, with any line you add under it. When `/retry` sends a reopened chat's message again, an `@` reference inside a file that message attached stays text.
- `@file:` reads a large file with non-English text up to the size limit instead of refusing it, returns the lines you asked for even far into a big file (or says plainly when they are past its end), and refuses a pipe or device instead of freezing the turn.
- A wildcard at the start of a word, such as `git grep -e x *` or `rg x *.rs`, no longer lets a command run as a read without a check when that command has an option that runs a program or writes a file (git, `rg`, `sort`, `kubectl`, `date`), since a file named like an option, such as `-O<program>`, takes the wildcard's place. `uniq` with any wildcard is not a read either, since it writes to its second file. Ask mode now shows an approval card for these, and Auto mode no longer lets them, `git add *` or `gh pr view *` skip the review as routine. The check reads the words with their quotes removed, so a quoted wildcard such as `rg -g '*.rs' x` counts too. A wildcard after a folder (`src/*.rs`), in an option's value (`--glob=*.rs`), or after a `--` that ends the options (`git log --oneline -- '*.rs'`, `git diff --stat -- '*.rs'`, `git grep -n TODO -- '*.rs'`), and reads such as `ls *.rs`, `cat *` and `grep -r x *`, run as before. A `--` right after an option that can take it as its value, such as `git grep -e -- *`, or after an option the check doesn't know, doesn't end the options, so that command asks.
- A wildcard in the words before the command, such as `timeout * git log`, `env -u * git log` or `nice -n * git log`, now gives the command no pass, since the file names it lists can name the program that runs (`timeout 0 sh zz git log`). Ask mode shows an approval card, Auto mode sends it to the review, and allow rules and Always grants don't cover it. The same wrappers with plain values, such as `timeout 5 git log`, run as before.
