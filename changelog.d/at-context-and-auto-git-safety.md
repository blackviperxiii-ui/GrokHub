- Auto mode: `git fetch` and `git pull` skip the review only with everyday options written out in full that take no value, and a plain remote, path or https or ssh address with plain branch names. Anything else, such as `--upload-pack`, `-j 4`, `--depth 1`, a shortened option, `--`, a wildcard such as `git fetch *` or another transport, now goes to the review, and to an approval card when that review blocks it.
- A git command pointed at another folder, such as `git -C vendor/lib log -p` or `env -C vendor/lib git fetch`, no longer runs without a check, since the settings of a repository in that folder can name programs to run. Auto mode now reviews it, and Ask mode shows an approval card. The same goes for a command run through `env` with another program search path (`-P`) or name (`-a`). `git -C .` runs as before.
- `@diff`, `@staged` and `@git:N` no longer run programs that a repository's settings name (external diff tools, text conversion, filters, signature checks), including settings pulled in by `include.path`, the settings of a submodule with changes of its own and a filter added while the diff runs.
- Only the words you type have their `@` references read. One in the main reply quoted into a side question, in a side answer sent on to the main task (also with Focus help on), in a Pulse card's report, in a Workboard card's notes, or in the message Resume sends for a Workboard card or a Code tab session (built from its checkpoint) stays plain text. A suggestion button under a reply never carries an `@` reference, since tapping it sends words the reply wrote.
- `@file:` reads a large file with non-English text up to the size limit instead of refusing it, returns the lines you asked for even far into a big file (or says plainly when they are past its end), and refuses a pipe or device instead of freezing the turn.
