- Settings → AI models: after a provider key or grant is saved, the status says to pick one of its models under "Use for your chats"; the pick lists free tiers first and marks them, and Off reads "Auto: xAI and Local AI".
- Chat: an OpenRouter model your account's privacy settings (zero data retention or a guardrail) leave no endpoint for now says so and what to do, instead of the raw HTTP 404 text.
- Local AI (Windows): the governor no longer throttles the on-device model because Loadout's own maximized window is in front; only another app's fullscreen window counts.
- Settings → AI models: OpenRouter's free and Auto routers lead the "Use for your chats" list, and new OpenRouter routing rows set the endpoint order (cheapest, fastest, lowest latency), a fallback to OpenRouter's router when the picked model has no endpoint, and the data policy (zero data retention only, or allow). They go out as OpenRouter's `provider` and `models` request fields and only to openrouter.ai.
- Settings → AI models → Local AI: "Local AI for chats" sends your chats (or everything the device can run) to the on-device model while online; Context size, GPU offload, CPU threads and Keep the model loaded set the launch; three governor switches (games and fullscreen apps, battery, idle) write `local/governor.json`.
- Local AI: a game, a fullscreen app or a deny-list app now unloads the on-device model (GPU and RAM go to the game; it loads again on the next ask once the game is gone) instead of only throttling it, unless the model is the only one that can answer (offline, cloud down, Local AI first), which throttles as before. Settings → Local AI → "When a game or fullscreen app runs" picks Unload, Slow down or Ignore.
- Local AI: the on-device model's reply now reaches the chat (it was saved to the session but never streamed to the screen), and a long chat is trimmed to the device's window on the way (oldest turns first) instead of being refused for its length, with or without tools.
- Linux: closing to the tray no longer maps the window straight back. The cabin stops re-sending the unmap after 1.5 s and never treats X11's stale focus on the hidden window as a taskbar click; the tray's Show or a second launch brings it back.
- Local AI: every launch and relaunch of the on-device model is sized to the GPU memory and RAM free right now, not to the setup-time probe. With "Share with the game", a game that takes GPU memory moves model layers to the CPU and shortens the context on the next relaunch (and again when it takes much more), and the model grows back once the game ends.
- Internal: tests that set `GROKHUB_CONFIG` now put the previous value back instead of unsetting it, and an unpinned test falls back to a temp folder, so a plain `cargo test` can no longer rewrite the real config stores with defaults (it did).
- Windows: a window saved as maximized comes back maximized. The native fill of the work area now runs on the frame after winit's own maximize flag is cleared; before, eframe applied that clear at the end of the same frame and shrank the window back to its saved size.
- Chat: the standing "sign in" note no longer sits above the composer. It posts once to the bell (Notifications) with a Settings pill that opens AI models; the card after a refused send stays where the message is.
- Settings → AI models → "Models Auto may use": for every model Auto can see (xAI, Anthropic, OpenRouter, the on-device tiers) say where Auto may send it on its own (everything, chats, coding and plans, background work, never) and the reasoning effort it sends; a provider model you allow joins Auto's ranking, a model set to Never leaves it, and a pinned default or "Use for your chats" still wins. `/why` shows `prefs:auto_provider` and `prefs:effort` when a preference decided.
- Settings → AI models → "Use for your chats" → "Auto: all models (xAI, your providers, Local AI)": one Auto for every model you connected. Each step ranks xAI, Anthropic, OpenRouter and the on-device models together (your plan's routing table first, then fit for the step, then cost), with no xAI sign-in too, and picks up models as providers add or drop them. In a tight week (80% of the budget) it takes the model that answers for the least without a recent 429 or slowdown (`/why`: `auto:efficient`). Provider models over your $/M ceiling, and safety, embedding and rerank models, join only through their own preference.
- Local AI: "Local AI for chats" gives way to the cloud while a game or a busy GPU has the governor throttling the device; the device stays the fallback. It also gives way to a pinned model and to the cloud check after an on-device answer failed verify.
- Chat: a reply from the on-device model or a provider model now knows which model it is. Every call routed away from xAI's Grok gets one line naming the model the router picked and who serves it, so "which model are you?" no longer gets an insistent "Grok".
- Local AI: the free-VRAM baseline for a relaunch is taken once the model is loaded, so the model's own memory no longer reads as a game taking the GPU (it restarted the model over and over on battery); battery or heat alone never restarts it.
- Local AI: the Settings rows write only their own switches into `local/governor.json`, keeping hand-edited allow and deny lists; a picked Context size survives the hardware probe; one message longer than the device's window keeps its start and end instead of being refused; the tuning rows show only while Local AI is on and installed.
- OpenRouter: the fallback sends only the router in `models` (the picked model was tried twice), its hint says it fires on any error and bills the model that answered, and the privacy-settings message is shown only for openrouter.ai replies.
