- Chat: an edit to a source file now counts as checked only after a command that runs, such as a test, build or lint run, or running the changed file. A re-read, `git status`, `git diff`, a viewer such as `cat`, `sed -n`, `Get-Content` or `echo`, or a test word inside a commit message, a grep pattern or a here-document no longer clears it. `cargo test 2>&1 | tail -20`, `npm test > /dev/null` and `make > build.log` still count as a run; `cargo test | grep -i fail` and a test runner's own filter (`pytest -k update`) are no longer read as a change, and PowerShell's `$out = cargo test` counts as the run it is. The shell's `test -f` and `[ … ]`, `pip show`, a PowerShell index, property or loop (`(Get-Content f)[0..40]`, `$c[10..30]`) and a `$(…)` path no longer pass for a run, a viewer a change pipes into (`npm install | tail`) no longer checks that change, `mvn install` counts as a build, and PowerShell writes such as `Add-Content`, `Out-File` and `Copy-Item` count as changes. A PowerShell path ending in `\"`, a backtick inside a quoted commit message and a `<<\EOF` here-document no longer hide the commands after them. Every unchecked change is listed by its full path, not only the newest one, and a re-read must name the same file, not just a file with the same name.
