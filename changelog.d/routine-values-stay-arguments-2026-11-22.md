- Routines: a filled-in value can't turn into an option (`--upload-pack=...`) or into code. A step that puts a value where the shell or a program runs it (`sh -c`, `eval`, `[[ ... -gt ]]`, a pipe or `<(...)` into an interpreter, a heredoc or comment, backticks or `${...}` inside quotes, a variable name for `read` or `printf -v`, the program name, `sed` or `awk`'s script, the command after `ssh host`) is refused when the routine is saved. So is any value in a command with a part nested in quotes or substitutions that has quotes of its own (`"$(date +"%F")"`): write that part plainly, or use a script step. On Windows, a value with `"` isn't passed to a program, nor one with `& | < > ^` to a program that may be a batch file (named without `.exe`), since its command line or cmd.exe could split or run it; cmdlets still get it. A value refused at run time stops the run instead of going to a repair, and a dry run shows the refusal.
