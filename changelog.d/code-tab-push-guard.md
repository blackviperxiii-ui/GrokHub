- Code tab: the agent's push guard now refuses a force-push, a push to main (also as `heads/main`, `HEAD` after a command that can switch branches, or a branch the repo's `remote.origin.push` or `push.default=upstream` sends to main) and a push through a git alias, however the command spells git: behind `env`, `setsid`, `nohup`, `timeout`, `stdbuf`, `flock`, `bash -c` and other wrappers, with `g\it` or `$'\x67it'`, or after a `PATH` change that turns an installed `git-<name>` program into an alias. Any other command in which the shell could run git asks first on a card in every mode unless every git in it is read as a git command that can't push: one built when it runs, fed to a shell, run by `find -exec` or `xargs`, an editor or `ext::` transport that runs a program, a git config write, or an installed program such as `git lfs` or `git subtree`. Ordinary commits, status, diff, log and add run as before whatever their message says. A program that builds a git command at run time (`python -c`, a compiled tool, a script file's contents) is outside what the guard can read.
