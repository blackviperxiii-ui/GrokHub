# Bug hunt, 2026-10-08

Base: `beta` @ `3bce32f853a7baa84e0eaf3287c01119dff59718` (after the 2.10.95 and 2.10.96 landings), then merged with `beta` @ `7afcebd` (main synced into beta, #574).
No open PRs held any files when this started, so nothing was off-limits.

How it was searched: `cargo clippy -W clippy::unwrap_used -W clippy::expect_used -W clippy::indexing_slicing` (771 hits, used as a finder only) and `clippy::string_slice` on grokhub-core; a manual sweep for `String::truncate`, `drain`, `split_at` and byte cuts on `&str`; reading the approval gate (`harness/hard.rs`, `perm/`, `harness_ui.rs`), redaction, persistence and exit paths; `cargo audit` (RUSTSEC-2026-0285 in rustls 0.23.43 was already fixed on beta by #558; the two remaining warnings are `proc-macro-error` unmaintained and `glib` unsound iterator, both transitive GTK deps); `cargo machete` (unused `base64` in grokhub-app, removed in the deslop PR).

Severity: P0 crash, data loss or security; P1 wrong behavior; P2 minor.

## Checked and fine

- The other `&str` slices: indices come from `find`/`char_indices` on the same string, an ASCII-only lowercase (same byte offsets), or an explicit `is_char_boundary` walk.
- Indexing hits: bounds-checked loops, count-checked `splitn`, positions from `position`/`enumerate`, non-zero `% len`, `json!` objects the code built itself.
- No std lock is held across `.await`; every HTTP client sets a timeout; retries have limits and backoff.
- `app.json` loading: every field defaults, a bad file is moved aside, writes are temp + sync + rename.
- Provider keys go only in headers and errors are redacted; no `Debug` print of `Secrets`, `AppConfig` or spawn options.
- Proactive auto-act can only add or turn off a connection; adding one that needs a token is a Credentials card.
