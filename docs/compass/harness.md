# Compass: Spike-0 harness (approval gate)

## Owns
- The cabin pre-check in front of Grok Build tool execution: hard floor (refuse, no bypass), hard class (park a card, even under Always), and the Access ladder (`AccessMode`: Readonly / Supervised / Full). Spike-1a safety loop: detectors in `detect.rs` (`claimed_click_no_change`, `action_loop`, `done_without_criteria`, `unsupported_assurance`, each citing span ids and quoted fields), the two-pass `audit.rs` (pass 1 digests, pass 2 full spans for flagged turns only), and `ladder.rs` (retry once, backtrack, then a soft pause; hard class always pauses). The cabin runs it at turn end (`harness_turn_end`) and writes `reply` / `harness_recovery` spans.
- One entry, `harness::decide`, for paths A (`grokhub-desktop` MCP), B (ACP ask), C (headless `grok -p` `--deny` rules), D (Grok Build's own computer use), and E (native Lab engine). Every step writes a span. Spike-1c path D: the lock is `BUILTIN_CU_DENY` (`--deny` on every `grok -p` when desktop control is off, or on Auto / Always with it on; added in `apply_desktop_spawn_args`). The belt is `harness_watch_cu`: a computer-use frame no path B ask covered goes through `decide_unasked` (`path_d.rs`). Soft writes a `path:"D"` allow; Readonly or hard stops the turn (`halt_in_flight`, parks kept like a Steer) with a deny span, and hard also parks a `ParkSource::Unasked` card whose Approve re-runs the step once on ACP Ask. The watchdog is a belt: a fast step can finish before its first frame. On ACP a pending frame waits for GB's ask. GB rules can't name a built-in (non-MCP) tool (`GB_DENY_GAPS`). Spike-2a: Cua Driver calls from `grokhub --mcp-cua` (`CuaProxy`) are mapped by `cua_as_desk` into `desk_classify`, park through `park_desk_call` (the path A card), and write `driver:"cua"` spans; `ComputerUseBackend::selected` is Grok Build unless the `cuaDriver` flag and desktop control are both on (Linux). Spike-2b: a click is classified by its target (`click_target_class` / `click_rule` in `hard.rs`, whole-word labels, a declared hard `effect` first). Path A reads the control at the point before `decide` (`DesktopServer::click_target` → `DesktopBackend::target_at`: AT-SPI on Linux via `atspi_target_at`, capped at `ATSPI_HIT_CAP` 300 ms; the default, Windows included, is unknown) and puts it in the `_target` hint; the Cua proxy reads the named `element_index` from the `get_window_state` it already takes before a click. Paths B and D read the quoted label in the ask or frame. Spans gain `target` (`ax` / `args` / `unknown`) and `target_rule` (`send:Send`); the hint and the window title never reach a span. `use_tool` is classified as the tool it names, and a denied hard step in a native batch stops the rest (`gate::NOT_EXECUTED`). Spike-3b episode: a message typed while desktop control is on opens one episode per chat (`EpisodeUi`); every span carries its `episode` id (cabin `write_span_at`, `turn.json`, the kernel), Steer keeps it, Halt / Stop / `EPISODE_IDLE` end it. On the native engine `run_episode` is the loop (observe, propose, `decide`, run or park, observe, claim): each step starts fresh from the `EpisodeView` (`VIEW_BUDGET_BYTES`, folds via `background:compact`, read-only `zoom`), hard steps park as `PARK_PREFIX` files the cabin card answers, `EPISODE_MAX_STEPS` / `EPISODE_MAX_WALL` pause with a counted `episode_cap` card, and it ends only on `GOAL_COMPLETE` plus `verify_gate` (fresh context, goal plus final `Observation` only, `background:judge`). Model calls go through `route::call_model` (`ModelCall`, `CallTokens` on the span).
- Spike-4a trust floor: `ConsentLedger` (`consent.jsonl`, user-click grants only), scopes all off (`Step::Scope`), and `guard_egress` (`Step::Egress`, log in `egress.jsonl`) on cabin-owned xAI calls and `/sync` (only once a computer is paired). Spike-4b seals both files at rest (`at_rest.rs`, key in the OS keyring, fail closed). Spike-5 / 5b: `ChangeLedger` (`changes/skills.jsonl`, `changes/connections.jsonl`, `changes/automations.jsonl`, kept copies per id, `HISTORY_CAP` each) under every self-managed write: nightly skill patches, the native `connection_*` and `scheduler_*` tools, and Ideas Add / Automate offers. Undo, restore, and Keep need an `UndoAsk`. `scope_guard` refuses harness policy, consent, egress, Access (`app.json`), the ledger itself, and `.grok`, and logs a `ledger_scope_violation` to `changes/findings.jsonl`. At most `SELF_AUTOMATION_WEEK_CAP` (2) new agent-made automations a week until the user keeps one. Spike-3a, read-only on spans: at turn end in memory repo mode, `trail.rs` writes one AMR `trail` node per turn (see [amr](amr.md)), and `span_search.rs` (`search_spans`) gives History and palette search their tool-step rows (`chat · turn N · tool · decision`) straight from `spans/*.jsonl`. Newest files first, capped at `SPAN_SEARCH_FILES` (200) files, `SPAN_SEARCH_LINES` (20,000) lines, `SPAN_SEARCH_HITS` (40) rows; no index file, and it works in legacy mode. Enter (or a click) opens the chat and scrolls to that turn's Work card (`jump_turn`, `turn_jump_row` in `crates/grokhub-app/src/app/step_search.rs`).

- `crates/grokhub-agent/src/harness/approval.rs`: `decide`, `decide_harness`, `APPROVAL_TTL` (300 s), `hard_card_key`.

Spike-3b: `crates/grokhub-agent/src/episode/kernel.rs` (loop, parks, fan-out), `crates/grokhub-agent/src/episode/view.rs` (view, folds, zoom), `crates/grokhub-agent/src/episode/verify.rs` (VerifyGate), `crates/grokhub-agent/src/route/mod.rs`, and `crates/grokhub-app/src/app/episode_ui.rs` (header, pause card, Halt / Stop / idle). `crates/grokhub-agent/src/harness/trail.rs` and `crates/grokhub-agent/src/harness/span_search.rs`: Spike-3a trails and session search (`read_spans_tail` in `span.rs` reads the last 4 MiB and skips a bad line).
- `crates/grokhub-app/src/app/harness_ui.rs` (cards, paths B/C/D/E) and `crates/grokhub-app/src/desktop_mcp/harness_gate.rs` (path A). `crates/grokhub-app/src/app/inbox_ui.rs`: Spike-1b decision inbox. The needs-attention line opens into one row per `decisions_waiting()` item on Home and the Workboard; a row answers through its card's own function (`resolve_hard_park_at`, `answer_perm_at`, `answer_soft_park`), so both write the same span. `crates/grokhub-app/src/app/change_undo.rs`: Work-tree rows (Undo / Keep, click only), `SelfChange` Home updates, `/connections changes` and `/automations changes`.
## Change recipe
- New hard pattern: classify it in `hard.rs` (add a head or name word to its const list), add the matching `Bash(...)` / `MCPTool(...)` rules to `HEADLESS_DENY_RULES` (five forms per shell head: bare, `sudo`, after `; `, `&& `, `| `) or a `GB_DENY_GAPS` entry if GB rules can't express it, then bump the literal count in `headless_deny_rules_cover_the_floor_and_stubs` (202 today). `gb_deny_rules_cover_every_hard_name_and_command` fails on a missing rule. A click label rule goes in its `CLICK_*` list (longest phrase first), with a `CLICK_TABLE` row and any look-alike.
- New caller: build a `Step` and call `decide`; never add a side path around it. A new model call in an episode goes through `call_model` with its class; never hand VerifyGate the view or the worker's reasoning (`verify_gets_only_the_goal_and_the_observation_and_a_reject_stays_flagged`), and only a `Continue` built from typing or a click resumes a cap pause. New outbound call: wrap it in `guard_egress` with honest `DataClass` values.
## What breaks it
- Anything that loosens Grok Build: an allow rule, a looser `--permission-mode`, or a `~/.grok` edit. The cabin may only tighten (`docs/superpowers/specs/2026-08-19-grok-build-gui.md`, Spike-0 addendum).
- Writing a `Grant` from anything but a Settings click (`only_a_settings_click_writes_a_grant`), building an `UndoAsk` outside typing or a click (`only_typing_or_a_click_builds_an_undo_ask`), putting skill, job, or server text in the ledger, a token in a connection entry, logging content or raw secrets to `egress.jsonl`, or writing learned data as plain text when the key is missing (`no_keyring_fails_closed_and_writes_nothing`).
- Letting Always-approve imply Full (`always_does_not_imply_full`) or Enter approve a hard card or a hard inbox row (hard Approve uses `clicked_by(Primary)`, never `clicked()`), or treating a delete as soft: every delete shape (`DELETE_HEADS`, `DELETE_PHRASES`, `find -delete`, the Recycle Bin verb, `delete_files`, and Delete on a file manager window) is hard class Delete under any mode (`every_delete_shape_is_hard_and_copy_open_stay_soft`). Search or trails reading anything but redacted span fields, or running anything: they only read (`click_ok_finds_the_step_row_newest_first_and_skips_unknown_chats`, `caps_hold_on_three_hundred_files`). Scratch chats stay out of step search.

## Non-obvious
- The harness lives in grokhub-agent, not grokhub-core, even though the desktop MCP and ACP paths use it.
- The floor covers shell commands only (same scope as `host_safety`); read-only tools are never hard class.
- Park handoff is files: `{config_dir}/harness/park`, plus `harness/turn.json` so the `--mcp-desktop` process writes spans into the open chat's `spans/<chat>.jsonl`. No answer in `APPROVAL_TTL`, a halt, or a closed cabin means Deny.
- A Steer keeps every parked card (`take_parks_for_steer`): a park holding the stopped turn's GB ask or desktop call is denied with a span and kept as `ParkSource::Held`. Ladder pauses (`soft_parks`) count in the needs-attention line and are answered by the user's own next message (not a Steer or a queued one), their card, or an inbox row. Tray Halt (`halt_everything` → `halt_inbox`) denies every inbox row with a span; Stop and Steer do not. Typing into a password, PIN, OTP, 2FA, or verification-code field is hard class credentials (`credential_field`: AX role or label, field-name hints, or a secret flag). The value never reaches the park file, card, or span (`credential_action`).
- The ledger records changes and never approves them; `harness::decide` stays the only gate. A connection or automation that holds anything `redact_secrets` would change is never kept or changed (the write rolls back). Undo of an automation reloads the cabin's in-memory list, or its next save would undo the undo. Spans only gain `#[serde(default)]` fields (`origin`, `consent_ref` are the newest); old lines must still parse. Typed text is stored as its length.
- Grok Build's own traffic is outside the cabin (owner decision D1); egress only guards calls GrokHub makes itself.
- Only `main` calls `use_os_keyring`. Every other process and test defaults to a store with no key, so `test_dir` and `use_test_key_store` register a `MemoryKeyStore`. The keyring entry is `GrokHub` / `learned-tier-key`; `learned-key.id` holds only a hash. User copy names the store per `KeyringOs` (Windows never says Secret Service), and `recheck_keyring` only drops the cached answer for Try again.
- Hard and ACP cards share `approval_card_width` (`APPROVAL_CARD_MAX_W`, 520) in `harness_ui.rs`, and `paint_approval_stack` keeps them left-aligned even on the centered empty chat; Esc denies a hard card. The Grant full card shows only with `GROKHUB_GRANT_FULL=1`: `grant_full_card_on` is read in `Cabin::new`, not `quiet_for_test`, so tests set `full_card_on`.
- GB `PreToolUse` hooks are not the lock: they fail open. `CLI_CREDENTIAL_DENY` from grokhub-acp rides along on path C.
