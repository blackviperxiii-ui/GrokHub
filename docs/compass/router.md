# Compass: router (R0 model registry, R1 automatic effort, R2a model healing, R2b cost classes, R3a learning, R3b providers)

## Owns
- The model registry in `{config}/models/registry.json`: which Grok models exist, which this plan or key can use, and their state (`ModelState`: probing, live, degraded, quarantined, not_in_plan, redirected, ghost, retired, pruned). Sources share one `CatalogSource` trait; `XaiApiSource` and `ProviderSource` are the only router code that touches the network.
- Passive health from real calls (`Observation` lines in `models/health.jsonl`, folded by `fold_health`). No health probes; the onboarding probe (`run_probe`) is the only one, and it only runs on `included` routes.
- Model profiles in `models/model_profiles/` (`ModelProfile`, versioned, last 3 kept) and `RuntimeSettings::from_profile`, which fill the route record's `settings`.
- `Router::choose` (pure: inputs, registry and profiles passed in, `now_ms` as the clock) and the `RouteRecord` on each `model-calls` span.
- R1 automatic effort: `POLICY_LIVE` is true, so every call in a class `CLASS_TABLE` lists sends the router's effort; an unlisted class (`background:unattended`, `eval:item`) keeps its own. `MODEL_LIVE` is true since R2a (below). There is no effort setting: no composer pill, no Settings row and no slash command. A saved `reasoningEffort` loads into legacy_reasoning_effort, is dropped and logged once (`models/router_notes.jsonl`).
- The ladder (`ladder.rs`): start from the class row, d < 0.3 one down (not below the floor), d > 0.7 one up (never past High on d alone); "think hard" goes to the ceiling and "keep it quick" to the floor, for one episode (a new user message is a new episode). E1 tool error or detector finding, E2 VerifyGate reject (3rd `E2:recovery`; the 1a recovery ladder owns retry/backtrack/pause), E3 correction, undo or "try again" (the next turn starts one up), E4 low self-check (no source yet), E5 `prepare:hard` never below High, E14 reasoning that spent the output budget with no answer (`TurnOutput::out_of_budget`). A4 loop signals (`Stage`, from `note_tool_run` in `run::push_output`; denials and refusals never count): the same tool failing twice, a repeated call, a failing test or build after an edit, `EXPLORE_LIMIT` lookups with no edit each climb one rung (one per step); a read-only step runs at low for that call only (`A4:digest`); `SETTLE_STREAK` steps of working edits or passing checks settle one rung (`A4:settle`). E15: a failure climbs effort first; `NEXT_MODEL_AFTER` failures at a rung that can't climb log `E15:next_model`. A3: a destructive or security turn (`ask::stakes`) takes the `prepare:hard` lane. DE1 three clean steps one down (DE1 and A4 never below the start of a Flagship lane), DE2 known routine (R3 stub), DE3 budget >= 80% (no budget source yet). No de-escalation in `prepare:hard` or after a reject until VERIFY_OK. With `care_first` on, `hold_chat_drops` keeps `chat:default` off the low-difficulty drop and off DE1 and DE2; DE3 still drops and keyword steer is ignored. Background classes never move except by DE3. Clamping rounds up going up and down otherwise, never below the floor. B7: with the embedding model on disk (`memory_embed`), `blend_turn` blends the ask read with its 50 nearest labeled turns (`ask_set` plus learned ones in `models/ask_bank.json`: embeddings, kinds, lanes, rungs and outcomes, never text, `BANK_CAP` oldest-out); a thin bank keeps the rules (`knn:thin`), strong agreement wins, a split leans higher, a stakes turn only rises, and 18+ or banned turns never touch it.
- The accuracy guard (`guard.rs`): 10% holdout by FNV of the episode id, user-facing listed classes except `prepare:hard`, at fixed High (rule `holdout`, never in the reason). Hourly, per class with n >= 50 per arm, Auto more than 2 points below the holdout raises the class start and floor one rung (`models/route_overrides.json`) and tells no one: which effort a class starts at shows nowhere. Success is the Spike-7 outcome; a lane with no outcomes is judged on the learner's settled turns (`bandit::guard_stats`, holdout turns logged at p = 1 and never learned from). With neither it logs "guard waiting on outcomes" once a day.
- R2a model picking (`Router::pick_model`): only routes `spend::allowed` admits (no sign-in keeps the call's own model, `cost:not_included`; a key with no table row keeps it too, `key:keep`). One model per episode (sticky per episode key, class and turn); it changes only at a new user message, on `E15:next_model` (the strongest xAI model above the episode's, then the strongest provider model you set up, else it stays), or when the episode's model is unhealthy and a healthy one exists. D12: a typed chat past `SESSION_KEEP_TOKENS` (16k) keeps its model between turns (`pin:keep`), moves up whenever a turn needs a stronger model (`pin:upgrade`), and moves down only when `policy::pin_switch` finds the saving over `expected_remaining_turns` (at most `PIN_TURNS_CAP`) beats re-sending the history uncached (`pin:downgrade`). D13: `session_metrics.rs` keeps each chat's cache hit rate, model switches and escalation precision in `models/session_metrics.json` (`SESSION_METRICS_CAP` chats, counts and model ids only, never shown); `summary` is `TuneRun.sessions`. A pin is kept while it answers; otherwise its redirect successor, then its family newest first (`fallback_chain`), then the table. Nothing healthy pauses the call (`NO_ROUTE_MSG`, nothing sent, `take_no_route`). the breaker (`health.rs`): 3 hard failures in a row (5xx or a timeout) or one listed 404 quarantine a model; backoff 1m/5m/30m/2h/12h with full jitter, then one half-open check that shares the onboarding probe's daily cap. Retired and pruned rows are tombstones, deleted 30 days later (`Deleted` event).
- The routing table (`table.rs` + `capabilities.rs` + `attention.rs` + `feedback.rs`): Cheap/Workhorse/Code/Flagship baseline lanes (`baseline_score`); each turn escalates/de-escalates via built-in signals + learned bias (**no LLM**). `repair:diagnose` Flagship/ForceTop. Evals on `included` only. Heal in `heal.rs`; pin never rewritten.
- R2b cost classes (`cost_class.rs` `classify`, `spend.rs`, `budget.rs`): `included` (plan models; key models at or under the Settings price limit) goes freely. `autonomous_premium` (a `-fast` variant) only when `fast_verdict` finds you waiting live, a long chain or a time box at risk, never background/automation/proactive, only on a Grok Build sign-in (never a plain API key: the public API has no Fast variant), and the plain model when the week is at 80%. `premium` (over the price limit, priority, US endpoint, 16 agents) needs a `grant_premium` grant from the hard money card (`Step::Premium`); without it the step uses an included model (`cost:premium_ungranted`) and the cabin parks the card once. `extra_spend` has no code path and no URL. The week (`load_week`: `cost_in_usd_ticks` or prices × tokens; plan: 429 free-usage-exhausted) feeds DE3 at 80% (`budget_pct`); at 100% background pauses and chat asks (`BUDGET_ASK`); background stays under 15% of the cap. The cabin (`budget_ui.rs`) shows `EIGHTY_CARD` once a week and the upgrade nudge (`nudge_due`); `models/budget_notes.json` is cabin-written. Probes and evals use `probe_class` (plan only).
- R3a DE2 known routine (`ladder.rs` `routine_rung`, fed by `learn::routine_for` in `live::decide`): a task signature (`skill:<name>`, else the topic of the ask) with 3 successes at one lower rung within 14 days (and since its last failure) starts there. Never below the floor, never `prepare:hard`, never after a reject until VERIFY_OK, and "think hard" wins. R3a self-tuning (`tune.rs` pure, `learn.rs` I/O, hourly with the guard): scorecards per class, model and effort over 28 days (`models/scorecards.json`). The weekly pass (or a registry/profile change) proposes a class's first model or start rung. Cheaper/faster ones go shadow (200 steps, logged as `tune: shadow:<id>`) → canary (5% of eligible low-risk steps by episode: not `prepare:hard`, `repair:*`, holdout, a reject, a pin or a hard tool) → promote at n ≥ 50 when pass rate drops ≤ 2 pts, rework rises ≤ 2 pts and cost or p50 improves ≥ 10%, at most 2 a week. A promotion the canary passed is then weighed by the decision engine (`route/trust.rs`: `promotion`, `Trust`, rule `rule:router/<class>/<order|start>`, `tested` so it needs no yes answers first): the Router trust dial, Halt, quiet hours, a busy moment, the watchdog's pause and the day's budget hold it in its canary (`TuneRun.held`), two undos by the user refuse that kind of change for that class, and Undo, rollback and Kept feed the area's score. A drop within 7 days (n ≥ 30) rolls back at once and blocks it 14 days. Promotions and rollbacks write `{config}/route_tuning.json` through the ledger (kind `model`, id `route_tuning`, byte-identical Undo); `starts` merges over the class table (`Band::tuned`, clamped) and `orders` over the routing table at read time (`tune::tuned_table`), so `routing_table.json` stays R2a's and a rebuild can't drop a promotion. Anything that costs more also goes shadow, flagged, and promotes on its canary only with ≥ 5 pts more quality and a reward (quality − λ·cost) no lower than live; there is no card, line or Accept, and old router cards are dropped on load (`self_review::retired_card_source`). A shadow is judged on the learner's log first: with ≥ 20 matched turns its doubly-robust score must be within 0.02 of live (`bandit::ope`, IPS + DR), else it is rejected; after 14 days unjudged it goes to its canary. Per-user learner (`bandit.rs`): arms are model × effort from the registry (in-band rungs, eligible, `in_auto_pool`, pin switches only when `pin_switch` pays, xAI then one provider arm); Thompson sampling over reward per `lane|kind|difficulty` context with the read as prior steers ordinary chat turns through `Router::choose`; it explores up or sideways on 3% of low-stakes turns after 20 settled ones, never on hard, agentic, stakes, flagship, redo or attention turns, and never on the holdout, a canary, a sensitive, local or 18+ turn. Each turn settles on the next one (redo, tool trouble, a failed check, a code copy, cost) into `models/route_bandit.jsonl` (ids, contexts, probabilities and rewards only, 5000 lines) and `models/route_bandit.json`. The tuning and candidates stay in `route_tuning.json` and the tuner state, and show nowhere. The tuner refuses to run while the VerifyGate or outcome hook is a stub (`ready()`). R3a local model (`local.rs`): **Local route: off by default.** `app.json` `localModel` is false until Settings → Cabin defaults → "On-device model for background tasks" (`local_ai_ui.rs` set_local_model; the tick passes it to `local::set_enabled`, no restart). `local::enabled()` is the flag **and** `local::installed()`; `connectivity` (`Online`/`Degraded`/`Offline`) steers offline→local; `local::installed()` is a test fake or a llama-server binary + GGUF (`local_sidecar` / `local_http`: loopback-only, bearer token, health + restart, `chat_stream`). Env: `GROKHUB_LLAMA_SERVER` / `GROKHUB_LOCAL_MODEL`, else `{GROKHUB_CONFIG}/bin` + `models/*.gguf`. Without assets the toggle routes nothing; Set up opens the wizard on-device step (`app/setup_wizard.rs`). `local_sidecar::start` logs to `bin/llama-server.log`, backs off 10% on out-of-memory up to 3 times, then names the next smaller catalog model, and keeps what ran in `{config}/local/autotune.json`; the live governor (`local_governor.rs` pure, readers and the 2 s / 5 s-on-battery sampler in `app/local_signals.rs`, applied by `route/local_gov.rs`) moves RampUp/Normal/Throttle/Unload with hysteresis (5 samples down, 30 up, no step up within 2 min of a change): fullscreen or a game (Windows notification state + full-monitor foreground + PDH GPU without the sidecar's pid; R3b providers (`providers.rs`): **off until you add a key and allow the destination.** Settings → Cabin defaults "Add a provider" (https base URL, key into the OS keyring via `KeyVault`, never a file, span, ledger, log or model input); `models/providers.json` holds id, kind and URL only. OpenAI-compatible (`/models`, `/chat/completions`, effort `reasoning.effort`) or Anthropic (`/v1/models`, `/v1/messages`, effort `output_config.effort`); xAI's body is unchanged. Rows are `<provider>/<model>` (`SourceKind::OpenAiCompatible` / `Anthropic`), cost class `new_provider`, probe `not_run: cost_class`; the listing runs only with key and grant. Every request goes through `guard_provider` / `provider_or_park` (`Step::Provider` in `harness::decide`: your destination grant covering every class, chat alone is not enough, else a hard send card) and writes one egress line. A candidate only when `providers::usable` (key + grant covering the call's data; sensitive needs a grant naming it) puts it in `Spend.providers`, native call sites only (`RouteCall.providers`); taken by a table row, or by Auto's own pool (`provider:auto`) when it lists a price at or under the price ceiling and answers in text (ranked after xAI), or as the stand-in while xAI is down (`live::outage_stand_in`); never a cheapest pick or a tuner promotion. On OpenRouter Auto picks the model itself from the day's `/models` list (`LISTING_MAX_AGE_MS`), never `openrouter/auto`: `auto_pickable` wants `tools` on a tool step, `reasoning` on a reasoning lane, the context, a price under the ceiling, text out and no `expiration_date`. Each call sends `require_parameters` with `data_collection` deny by default, `models` as the pick and its backup (`openrouter_backup`), a hashed `session_id` and `reasoning.effort`. The stand-in ranks a provider busy or twice as slow lately (`lagging_providers`, latency EWMA `PROVIDER_EWMA_ALPHA`) after a healthy one. There is no user pin or pick: the router alone chooses. Permissions → Other providers: Allow parks the card (ParkSource::Provider), Revoke is one click. Saving a key is a hard credentials card first (ParkSource::ProviderKey, tool `model.provider_key`; the key waits in ProviderUi::pending, Approve calls `add_provider_as`, Deny/Esc/timeout drop it), then the send card. "Provider type" passes an API shape to `add_provider_as` for a proxy under another host (`None` detects from the host). "Get a key" opens `providers::key_page`; "Sign in with OpenRouter" runs `providers::openrouter_key` (PKCE S256 on the `loopback` redirect, code + verifier to `/api/v1/auth/keys` as a handshake send) and hands the key to the same credentials card. After a refresh provider_refresh_note counts the models a provider added (no names) or says it turned the key down (HTTP 401/403). Router + governor (`local.rs` `LocalCapacity`, `local_gov.rs`): `LocalGate.capacity` carries the governor level into `Router::choose`. Grok stays primary. Online, local takes background classes only in RampUp or Normal (`local:throttled` sends them to Grok under Throttle), and a heavy background step (over half the context cap) goes local only in RampUp (`local:heavy_waits`); `serve` holds a heavy step that still lands on the device (offline, cloud down) for RampUp up to `HEAVY_WAIT`. Offline and cloud-down work goes local at any level but Unload, where the step parks with `local:paused` and the chip "Local paused: game or low power" (no model-wait card). On-device route records carry `gov_state` and `tier`, and scorecards split by them. Settings → Local AI shows the state, level, tier, queue and log path (`local::status_lines`, painted by ui_local_model_rows). Level changes go to `{config}/local/governor.jsonl` (this device only, 7 days, deletable). Prompt tidy (`cleanup.rs`): `app.json` `promptCleanup` (off; Settings → Local AI, greyed out while Local AI is off, synced by `local::set_prompt_cleanup` next to `set_enabled`) lets `cleanup::tidy` send a typed chat ask to the already-loaded model (`local::warm_runtime`, never the router or the cloud) on one worker thread for at most `LIMIT` (300 ms, one call in flight); `keeps_meaning` drops any answer that changes a number, quote, path, URL, @-mention, a "not", a real word or the Brief's intent, care or domain, and `restore_typed` saves the typed text. Quota detection (`model_registry/quota.rs` pure state, `route/quota.rs` wire): OpenRouter `GET /api/v1/key` (FreeOnly / Paid / PaidLow / Negative; the free daily ceiling comes from `free_model_daily_requests.limit`, not `is_free_tier`), xAI `GET /v1/api-key` blocked flags, Anthropic from `anthropic-ratelimit-*` reply headers plus a local spend ledger priced off the registry table (cache writes at the prompt rate); checks ride the registry refresh (`RefreshJob.xai_bearer`), due every `QUOTA_POLL_MS` (10 min) or at once after a 402, 403 or 429 stamps `recheck_at_ms` (`providers::call_model` notes provider replies, `live::note_failure` native ones); Anthropic spend-limit 429 (`enforced_spend_limit_reached`, no Retry-After) benches to the 1st of next month, out-of-credit 400 for an hourly re-check; the scorer's hard filters read the ledger on every pick (`score:quota:*` in `route/score.rs`). Model cards (`model_registry/card.rs` + `ModelCard` on `ModelMeta`, mirrored into `ProfileMeta`): refresh stamps each row's `Route` from its sources via `record::route_for` (free vs paid from the one `discover::is_free_model`, which `providers::is_free_model` now delegates to) and fills unknown prices, windows and card priors from the bundled table — that table is what prices Claude (its listing names none, cache write at 1.25× prompt, read at 0.1×), so `auto_pickable` can admit it; listings always win, live data replaces priors. `Prices.cache_write` feeds `anthropic_call_ticks` (write rate when known, else the prompt rate). `ModelRecord::reliability` derives success/429 rates from the 7-day health window; `OpenRouterQuota::permits(free)` gates a route class on the detected account state. The scorer (`route/score.rs`, failover step 6) spends all this on every pick. Task sizing (`route/sizing.rs`, failover step 5): `estimate` sizes a turn up front (tiny / short / medium / long from difficulty, the ask lane, planned tools, plan mode, context, session-kept tokens and the class's learned output length — the third quartile of its finished spans, re-read at most every `LEARNED_EVERY_MS`); long is more than 8 expected tool steps, more than 4k expected output tokens, context over 64k, or a session past 16k kept tokens. `Router::choose` spends the class today (`RouteInput.size`): a long task drops free provider models from the candidate ids while a carrier route exists (`size:long:no_free`; free stays when it is the only cloud there is) and ranks the paid routes first, local after paid through its own branches below; the order inside the paid routes is the scorer's call (step 6 replaced PR 5's placeholder xAI-first sort with the weighed ladder). The routing rule as corrected 2026-11-07: longer runs never go to free models — they go to a paid provider or local, paid first — and less challenging work defaults to the device when a local model is already loaded: `sizing::warm_local_default` sends tiny and short turns to the admitted local tier when `RouteInput.local_warm` is set (live reads `local::warm_runtime()`, which never starts the sidecar), except under governor throttle (a game or a busy GPU), where only tiny turns default there, and never over an episode pin, an explicit pick, or the cloud-down fallback paths, which keep their own rules and cabin note (`size:warm_local`). A per-turn `TurnSizer` (static, keyed by episode + turn like the ladder's step count, fed what each call wrote and where it ran by `live::route_log`) upgrades a turn to long mid-flight — past 3 tool steps or 90 s on a free or on-device model, or past the long output/context lines on any route (`size:upgrade:long`) — so the turn's later picks and failovers treat it as long. The scorer and route ladder (`route/score.rs`, failover step 6) spend the full estimate: hard filters first — a need the card scores a plain 0 (`score:need:*`), a route the quota ledger has closed, a training route on a sensitive turn (`score:data:trains`), a model on tryout on medium or long work (`score:probation`; tiny/short turns carry it as risk instead) and a model that failed its tryout on any work (`score:probation:failed`), a free model inside its 14-day expiry stop-window (`score:expiring`), any cloud model at all on an explicit turn (`score:adult:cloud`, and `Router::choose` itself keeps an explicit call on the device whenever the device is a candidate, `adult:local_only`), the device for more than tiny work under governor throttle (`score:gaming:local`) — and the filters never empty the ladder (`score:filters_kept`: a working route beats a dead stop). Survivors sort inside the standing groups (the table's order leads its group outright, untabled natives next, untabled providers last; a long run's paid routes are one tier scored outright) by tier then weighed score: quality for the task's needs (capability priors, needs-weighted, capped at what the size can use), speed (card tps prior, live-replaceable), 7-day reliability, expected cost (free and the device at 1.0, plan models at a shadow of list, metered at list) and risk, under weights the turn's goal leans (`score:ladder` when the head moves). The bandit still steers ordinary chat after the pick. The hand-off packet (`route/handoff.rs`, failover step 7): a switch inside a call is recorded on its route record (`handoffs`: from, to, and an `handoff:*` rule naming why the model stopped — limit, credit, outage, stall, dropped, offline, auth) and the chat gets one plain line about the move with no model names in it; a step the run loop resumes carries one cabin note over the history the next model is sent anyway (the ask, tool calls and results, the plan's open items, a compacted summary standing in when the session outgrew the window) naming who stopped and why, which models already failed this step, which models answered the run's earlier steps and who wrote a kept partial reply, closing with the carry-on line. The packet is a header only, so it never grows with the session, and it is added only when the step did some work: a step that produced nothing is resent exactly as it was, a clean retry with nothing extra said to the model. Claude over the provider wire (failover step 8): Anthropic calls from `stream_routed` go through `providers::stream_model` and arrive as an event stream folded by `AnthropicStream` — text and thinking deltas as they land, tool calls assembled from `input_json_delta`s, usage (cache reads in `Usage.cached_tokens`, writes counted apart for the ledger) and the stop reason on the finished turn; the whole-reply `call_model` stays for the non-chat call sites. A failure after text showed is `ClientError::CutOff` (never retried, never failed over), before it the error itself (a stream with no `message_stop` is a disconnect); an in-stream Anthropic `error` event maps by its type. Every Anthropic body carries prompt-cache marks (`cache_mark`: the system text, the last tool and the last message block), so the prefix each turn re-sends bills at the cached rate. Stop reasons read one way in both paths (`note_anthropic_stop`): `max_tokens` truncates (`max_output_tokens`), `refusal` is `ClientError::Refused` — its own class, never retried or failed over, `handoff:refused` in the packet — and `pause_turn` ends the turn as it stands. OpenRouter over the provider wire (failover step 10): an OpenRouter call from `stream_routed` streams too — `prepare_call` sets `stream: true` and `stream_options.include_usage`, and `OpenAiStream` folds the chunks (`delta.content` and `delta.reasoning`/`reasoning_content` as deltas, `delta.tool_calls` assembled by index with id and name first and the arguments in fragments, `reasoning_details` merged by index so the text grows and the signature lands, the trailing usage chunk with `cost` as ticks, the chunk `model` tagging the reasoning for the pick or its backup). Both streams share one reader (`read_stream`: Stop, the 300s stall clock, which `: OPENROUTER PROCESSING` keep-alives hold off, and the cut-off rule); a stream with no `finish_reason` is a disconnect, `length` truncates, an in-stream `error` chunk maps by its numeric `code` like an HTTP status (a 429 is a rate limit the router fails over from before text showed, and stamps the quota ledger for a re-read), and a host that answered with the whole JSON reply is parsed whole and sent as one delta. Any other OpenAI-compatible host keeps the whole-reply call. The tryout (failover step 9, `model_registry/probation.rs` pure, `route/trial.rs` I/O): a model a provider starts listing after its first listing, and any row the bundled card table marks `probation`, starts a `Probation` on its record (`Stage::Trial`, a `probation` registry event) and its card carries `probation` while it lasts. Real calls count as they fold from the health log (an answer, an error, a limit or a 404 count; a refusal for the prompt or the account doesn't). Each refresh (`run_refresh`, after onboarding) sends free OpenRouter models on tryout at most 2 probes a run and 2 a model a day (`providers::probe_model`: a `record_number` tool call or a one-word answer, alternating, no backup, 512 tokens, class `background:probe`), only under a grant that already covers chat (`providers::usable`, never a card), only while the free route is open with 25 or more requests left today; a limit, a credit stop, a key or setup failure counts against the account, not the model, and a limit ends the run. Then `trial::judge` reads the learner's steps since the tryout began (`trial::quality_of`: its checked answers against every other model's in the classes it served, 20 checked on each side at least, worse by more than 5 points, or 2 once it has 50, is `Fell`) and `Probation::judge` decides: 5 calls with no answer, 20 or more under 90% answered, or answers that fell behind its peers fail it (`score:probation:failed` bars it on any turn), and 20 calls at 90% graduate it after 14 days, or after 200 calls whose answers held; a failed model gets a fresh tryout 14 days on. While on tryout it takes tiny and short turns only, and the canary (`RouteInput.probation_canary`, 5% of low-risk episodes by `tune::in_canary(key, "probation")`, never on a tuner mark, a pin, a step-up, a sensitive or 18+ turn) lets one lead a tiny or short turn with the ladder behind it (`probation:canary`; the bandit leaves that turn alone). The connection check (`route/check.rs`, the `models_check` tool and a `[Connections]` note on any chat turn that `check::connection_question` reads as asking about a key, a provider or which models can answer) reports from the wire: for each provider you added, key saved and allowed (`providers::provider_state`), a live listing read with that key (`providers::live_listing`, no data, the daily OpenRouter cache skipped), and a one-word reply from its cheapest routable model (`check::test_model`, sent with `providers::probe_model`); a provider that isn't allowed gets nothing, not even the listing, since the egress gate parks it. The reply is held to it: `post_check::connections` sends the model back when its reply states how a model or key stands with no check that turn (no `models_check` ran and the ask wasn't a connection question), or asks the user to update, restart, sign in again or send a harder task as the test; the `[Connections]` note says the app picks the model and the check is the test, both prompts say to name an id or result only from the model's own tool output (one changed line each, so the stable prefix doesn't grow and Background stays 30% under Chat), and an unknown task id now says no such task was started and lists the ones that were (`tasks::TaskHub::unknown`). The note rides in the same volatile write as the route note, is run once per turn (`check::report_for_turn`, two minutes), says whether Grok is signed in, and on an 18+ chat (`RouteCall.adult`) says why nothing in it goes online; it sends no chat text. The same pass logs a routable model whose announced expiry is inside the 14-day stop window once per date (an `expiring` event; the scorer already stops routing to it). Both are span events only: nothing in the chat names a model.

## Change recipe
- New model call site: send through `stream_routed` (native), `route::call_model` or `route::cabin::call_model` with its class. An internal site keeps its old effort by using a class whose start is that effort (`internal_call_sites_send_the_same_effort_as_before`).
- New class: add a `CLASS_TABLE` row (start / floor / ceiling) and a `plain` phrase for the reason.
- New listing field: parse it in `parse_model_row`, add it to `ModelMeta` with `#[serde(default)]`, keep unknown as `None`, and extend `merge_from`.
## What breaks it
- Treating 403 content-safety or 429 `free-usage-exhausted` as health (`content_safety_and_free_usage_change_nothing`), or counting an unlisted 404 as a ghost strike.
- Putting prompt text in a route record (`route_records_hold_no_prompt_text`), or a probe prompt built from user data (`probe_prompts_contain_no_user_data`).
- A new `ureq` builder in `sources.rs` without its `WRAPPED` count in `crates/grokhub-agent/src/harness/egress_coverage.rs`.
## What depends on it
- R3a fills DE2 and joins route records with `outcomes.jsonl` by episode. R3b's `new_provider` routes ride the same `Spend` and `harness::decide`.
## Non-obvious
- `harness::decide` stays the only approval gate: the router picks how to think, never whether to act. A GB-only model gets a metadata-only profile (`not_run: gb_only`); a queued probe is not usable yet.
- `PROVIDER_GROK_BUILD` (`grok_build`) is left from the CLI path: a call logged under it gets no outcome and no health (`crates/grokhub-agent/src/route/live.rs`). No CLI turn runs now; chat, background, and scheduled turns are native.
- The ladder's state is in memory per episode and class; tool errors and the A4/E14 stage signals reach it through thread-locals (`note_tool_error`, `take_stage`), so the next routed call on the same thread reads them.
