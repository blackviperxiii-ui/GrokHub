# Compass: router (R0 model registry, R1 automatic effort, R2a model healing, R2b cost classes, R3a learning, R3b providers)

## Owns
- The model registry in `{config}/models/registry.json`: which Grok models exist, which this plan or key can use, and their state (`ModelState`: probing, live, degraded, quarantined, not_in_plan, redirected, ghost, retired, pruned). Sources share one `CatalogSource` trait; `XaiApiSource` and `ProviderSource` are the only router code that touches the network.
- Passive health from real calls (`Observation` lines in `models/health.jsonl`, folded by `fold_health`). No health probes; the onboarding probe (`run_probe`) is the only one, and it only runs on `included` routes.
- Model profiles in `models/model_profiles/` (`ModelProfile`, versioned, last 3 kept) and `RuntimeSettings::from_profile`, which fill the route record's `settings`.
- `Router::choose` (pure: inputs, registry and profiles passed in, `now_ms` as the clock) and the `RouteRecord` on each `model-calls` span.
- R1 automatic effort: `POLICY_LIVE` is true, so every call in a class `CLASS_TABLE` lists sends the router's effort; an unlisted class (`background:unattended`, `eval:item`) keeps its own. `MODEL_LIVE` is true since R2a (below). There is no effort setting: no composer pill, no Settings row, and `/effort` only prints `EFFORT_AUTO_MSG`. A saved `reasoningEffort` loads into `legacy_reasoning_effort`, is dropped and logged once (`models/router_notes.jsonl`).
- The ladder (`ladder.rs`): start from the class row, d < 0.3 one down (not below the floor), d > 0.7 one up (never past High on d alone); "think hard" goes to the ceiling and "keep it quick" to the floor, for one episode (a new user message is a new episode). E1 tool error or detector finding, E2 VerifyGate reject (2nd at the ceiling logs `E2:next_model` for R2, 3rd `E2:recovery`; the 1a recovery ladder owns retry/backtrack/pause), E3 correction or undo (the next turn starts one up), E4 low self-check (no source yet), E5 `prepare:hard` never below High. DE1 three clean steps one down, DE2 known routine (R3 stub), DE3 budget >= 80% (no budget source yet). No de-escalation in `prepare:hard` or after a reject until VERIFY_OK. Background classes never move except by DE3. Clamping rounds up going up and down otherwise, never below the floor.
- The accuracy guard (`guard.rs`): 10% holdout by FNV of the episode id, user-facing listed classes except `prepare:hard`, at fixed High (rule `holdout`, never in the reason). Hourly, per class with n >= 50 per arm, Auto more than 2 points below the holdout raises the class start and floor one rung (`models/route_overrides.json`) and posts a Pulse Suggestion. Success is the Spike-7 outcome. With no outcomes it logs "guard waiting on outcomes" once a day.
- R2a model picking (`Router::pick_model`): only routes `spend::allowed` admits (no sign-in keeps the call's own model, `cost:not_included`; a key with no table row keeps it too, `key:keep`). One model per episode (sticky per episode key, class and turn); it changes only at a new user message, on `E2:next_model`, or when the episode's model is unhealthy and a healthy one exists. A pin is kept while it answers; otherwise its redirect successor, then its family newest first (`fallback_chain`), then the table. Nothing healthy pauses the call (`NO_ROUTE_MSG`, nothing sent, `take_no_route`). the breaker (`health.rs`): 3 hard failures in a row (5xx or a timeout) or one listed 404 quarantine a model; backoff 1m/5m/30m/2h/12h with full jitter, then one half-open check that shares the onboarding probe's daily cap. Retired and pruned rows are tombstones, deleted 30 days later (`Deleted` event); a retired pin shows "(retired)".
- The routing table (`table.rs`): `models/routing_table.json`, built from usable profiles, registry state and a fixed eval set (5 mechanical items per class), score = quality (or 0.5 unscored) minus cost and latency weights by speed/quality. Evals only on `included` routes, class `background:eval`, 60k tokens a build, one build a day, cached by (source_hash, eval set version, effort). A new version is a ChangeLedger line (kind `model`) with byte-identical Undo; 5 old versions kept. `/why table` and Settings "How Auto picks" show it. what the user hears (`heal.rs`): a pinned model resting is one Work-tree line; a retired, ghost or redirected pin, a plan change and a new model in the plan are one Home update each; no route is a pause card. Each incident posts once (`models/heal_notes.json`). `app.json` (the pin) is never rewritten.
- R2b cost classes (`cost_class.rs` `classify`, `spend.rs`, `budget.rs`): `included` (plan models; key models at or under the Settings price limit) goes freely. `autonomous_premium` (a `-fast` variant) only when `fast_verdict` finds you waiting live, a long chain or a time box at risk, never background/automation/proactive, never with the Settings toggle off, and the plain model when the week is at 80%. `premium` (over the price limit, priority, US endpoint, 16 agents) needs a `grant_premium` grant from the hard money card (`Step::Premium`); without it the step uses an included model (`cost:premium_ungranted`) and the cabin parks the card once. `extra_spend` has no code path and no URL. The week (`load_week`: `cost_in_usd_ticks` or prices × tokens; plan: 429 free-usage-exhausted) feeds DE3 at 80% (`budget_pct`); at 100% background pauses and chat asks (`BUDGET_ASK`); background stays under 15% of the cap. The cabin (`budget_ui.rs`) shows `EIGHTY_CARD` once a week and the upgrade nudge (`nudge_due`); `models/budget_notes.json` is cabin-written. Probes and evals use `probe_class` (plan only).
- R3a DE2 known routine (`ladder.rs` `routine_rung`, fed by `learn::routine_for` in `live::decide`): a task signature (`skill:<name>`, else the topic of the ask) with 3 successes at one lower rung within 14 days (and since its last failure) starts there. Never below the floor, never `prepare:hard`, never after a reject until VERIFY_OK, and "think hard" wins. R3a self-tuning (`tune.rs` pure, `learn.rs` I/O, hourly with the guard): scorecards per class, model and effort over 28 days (`models/scorecards.json`). The weekly pass (or a registry/profile change) proposes a class's first model or start rung. Cheaper/faster ones go shadow (200 steps, logged as `tune: shadow:<id>`) → canary (5% of eligible low-risk steps by episode: not `prepare:hard`, `repair:*`, holdout, a reject, a pin or a hard tool) → promote at n ≥ 50 when pass rate drops ≤ 2 pts, rework rises ≤ 2 pts and cost or p50 improves ≥ 10%, at most 2 a week. A drop within 7 days (n ≥ 30) rolls back at once and blocks it 14 days. Promotions, rollbacks and accepted cards write `{config}/route_tuning.json` through the ledger (kind `model`, id `route_tuning`, byte-identical Undo); `starts` merges over the class table (`Band::tuned`, clamped) and `orders` over the routing table at read time (`tune::tuned_table`), so `routing_table.json` stays R2a's and a rebuild can't drop a promotion. Anything that costs more is a Suggestion card in the Spike-7 weekly pass (≤ 2 a week, inside the 5; `self-review:router:<id>`), applied only on Accept. The weekly pass posts one Home line (`tune::review_line`); `/why table` adds the tuning, candidates and canary status. The tuner refuses to run while the VerifyGate or outcome hook is a stub (`ready()`). R3a local model (`local.rs`): **Local route: off by default.** `app.json` `localModel` is false until Settings → Cabin defaults → "On-device model for background tasks" (`local_ai_ui.rs` `set_local_model`; the tick passes it to `local::set_enabled`, no restart). `local::enabled()` is the flag **and** `local::installed()`; this build has no runtime (no new crates), so the toggle alone routes nothing and the row shows "No local model installed" with Set up, which opens the setup wizard's on-device model step (`app/setup_wizard.rs`). The wizard (welcome, app setup, on-device model) opens once on a fresh profile until `setupDone`; Settings → Behavior → Setup reopens it. Its local AI step reads GPU (`nvidia-smi`), RAM and free disk (`detect_hardware`), feeds `local::set_device` (`local_setup::low_end`), and shows `local_setup::suggest`'s pick (biggest of Qwen 2.5 7B / 3B / 1.5B that fits RAM or VRAM plus download + 2 GB disk) and the models folder `~/GrokHub/models`. Download (`model_download.rs` core, `model_download_ui.rs` app): `<file>.part` with HTTP Range resume (after Pause, a dropped connection or a restart), Cancel deletes it, then SHA-256 against Hugging Face's listed LFS `oid` (`tree/main` API); a match renames it and writes `installed.json`, and turns `localModel` on. No runtime runs the file yet, so `local::installed()` stays false and the rows say the model is downloaded but can't run. Off, `LocalSource` lists nothing and `Router::choose` drops any `local:*` id. On (tests: `ForceOn`, or `Installed` plus the flag, with a fake `LocalRuntime`): `local:<tier>` is `included`, has no effort menu and a 4k context cap, takes only background classify/triage/redact/summarize (never `prepare:hard` or a hard tool step), is the only route for sensitive data with no cloud grant, and writes no egress line; the downshift ladder only switches the live tier; PII is regex first, model second; `difficulty::estimate` uses it when on and R1's rules otherwise. R3b providers (`providers.rs`): **off until you add a key and allow the destination.** Settings → Cabin defaults "Add a provider" (https base URL, key into the OS keyring via `KeyVault`, never a file, span, ledger, log or model input); `models/providers.json` holds id, kind and URL only. OpenAI-compatible (`/models`, `/chat/completions`, effort `reasoning.effort`) or Anthropic (`/v1/models`, `/v1/messages`, effort `output_config.effort`); xAI's body is unchanged. Rows are `<provider>/<model>` (`SourceKind::OpenAiCompatible` / `Anthropic`), cost class `new_provider`, probe `not_run: cost_class`; the listing runs only with key and grant. Every request goes through `guard_provider` / `provider_or_park` (`Step::Provider` in `harness::decide`: your destination grant covering every class, chat alone is not enough, else a hard send card) and writes one egress line. A candidate only when `providers::usable` (key + grant covering the call's data; sensitive needs a grant naming it) puts it in `Spend.providers`, native call sites only (`RouteCall.providers`); taken only by your Settings pick (`live::set_provider_pick`, `provider:picked`), a pin, or a table row; never a stand-in, fallback, the cheapest pick or a tuner promotion. A provider pin without its key or grant stands in with xAI (`provider:ungranted`). Permissions → Other providers: Allow parks the card (`ParkSource::Provider`), Revoke is one click. Saving a key is a hard credentials card first (`ParkSource::ProviderKey`, tool `model.provider_key`; the key waits in `ProviderUi::pending`, Approve calls `add_provider_as`, Deny/Esc/timeout drop it), then the send card. "Provider type" passes an API shape to `add_provider_as` for a proxy under another host (`None` detects from the host). "Get a key" opens `providers::key_page`; "Sign in with OpenRouter" runs `providers::openrouter_key` (PKCE S256 on the `loopback` redirect, code + verifier to `/api/v1/auth/keys` as a handshake send) and hands the key to the same credentials card. After a refresh `provider_refresh_note` names the models a provider added or says it turned the key down (HTTP 401/403).

## Change recipe
- New model call site: send through `stream_routed` (native), `route::call_model` or `route::cabin::call_model` with its class. An internal site keeps its old effort by using a class whose start is that effort (`internal_call_sites_send_the_same_effort_as_before`).
- New class: add a `CLASS_TABLE` row (start / floor / ceiling) and a `plain` phrase for the reason.
- New listing field: parse it in `parse_model_row`, add it to `ModelMeta` with `#[serde(default)]`, keep unknown as `None`, and extend `merge_from`.
## What breaks it
- Treating 403 content-safety or 429 `free-usage-exhausted` as health (`content_safety_and_free_usage_change_nothing`), or counting an unlisted 404 as a ghost strike.
- Putting prompt text in a route record (`route_records_hold_no_prompt_text_and_why_prints_at_most_ten_lines`), or a probe prompt built from user data (`probe_prompts_contain_no_user_data`).
- A new `ureq` builder in `sources.rs` without its `WRAPPED` count in `crates/grokhub-agent/src/harness/egress_coverage.rs`.
## What depends on it
- R3a fills DE2 and joins route records with `outcomes.jsonl` by episode. R3b's `new_provider` routes ride the same `Spend` and `harness::decide`.
## Non-obvious
- `harness::decide` stays the only approval gate: the router picks how to think, never whether to act. A GB-only model gets a metadata-only profile (`not_run: gb_only`); a queued probe is not usable yet.
- Grok Build turns are logged at send (`provider` `grok_build`, no outcome, no health): GB owns those calls and its effort is set at spawn. Live ACP `set_config_option` is not verified (R0 Step-0), so an ACP session runs at everyday chat's start and `/why` notes when the router would have picked otherwise; a headless `grok -p` turn spawns at the router's pick for that turn.
- The ladder's state is in memory per episode and class; tool errors reach it through a thread-local (`note_tool_error`), so the next routed call on the same thread reads them.
