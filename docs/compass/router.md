# Compass: router (R0 model registry, R1 automatic effort, R2a model healing, R2b cost classes, R3a learning, R3b providers)

## Owns
- The model registry in `{config}/models/registry.json`: which Grok models exist, which this plan or key can use, and their state (`ModelState`: probing, live, degraded, quarantined, not_in_plan, redirected, ghost, retired, pruned). Sources share one `CatalogSource` trait; `XaiApiSource` and `ProviderSource` are the only router code that touches the network.
- Passive health from real calls (`Observation` lines in `models/health.jsonl`, folded by `fold_health`). No health probes; the onboarding probe (`run_probe`) is the only one, and it only runs on `included` routes.
- Model profiles in `models/model_profiles/` (`ModelProfile`, versioned, last 3 kept) and `RuntimeSettings::from_profile`, which fill the route record's `settings`.
- `Router::choose` (pure: inputs, registry and profiles passed in, `now_ms` as the clock) and the `RouteRecord` on each `model-calls` span.
- R1 automatic effort: `POLICY_LIVE` is true, so every call in a class `CLASS_TABLE` lists sends the router's effort; an unlisted class (`background:unattended`, `eval:item`) keeps its own. `MODEL_LIVE` is true since R2a (below). There is no effort setting: no composer pill, no Settings row and no slash command. A saved `reasoningEffort` loads into `legacy_reasoning_effort`, is dropped and logged once (`models/router_notes.jsonl`).
- The ladder (`ladder.rs`): start from the class row, d < 0.3 one down (not below the floor), d > 0.7 one up (never past High on d alone); "think hard" goes to the ceiling and "keep it quick" to the floor, for one episode (a new user message is a new episode). E1 tool error or detector finding, E2 VerifyGate reject (3rd `E2:recovery`; the 1a recovery ladder owns retry/backtrack/pause), E3 correction, undo or "try again" (the next turn starts one up), E4 low self-check (no source yet), E5 `prepare:hard` never below High, E14 reasoning that spent the output budget with no answer (`TurnOutput::out_of_budget`). A4 loop signals (`Stage`, from `note_tool_run` in `run::push_output`; denials and refusals never count): the same tool failing twice, a repeated call, a failing test or build after an edit, `EXPLORE_LIMIT` lookups with no edit each climb one rung (one per step); a read-only step runs at low for that call only (`A4:digest`); `SETTLE_STREAK` steps of working edits or passing checks settle one rung (`A4:settle`). E15: a failure climbs effort first; `NEXT_MODEL_AFTER` failures at a rung that can't climb log `E15:next_model`. A3: a destructive or security turn (`ask::stakes`) takes the `prepare:hard` lane. DE1 three clean steps one down (DE1 and A4 never below the start of a Flagship lane), DE2 known routine (R3 stub), DE3 budget >= 80% (no budget source yet). No de-escalation in `prepare:hard` or after a reject until VERIFY_OK. With `care_first` on, `hold_chat_drops` keeps `chat:default` off the low-difficulty drop and off DE1 and DE2; DE3 still drops and keyword steer is ignored. Background classes never move except by DE3. Clamping rounds up going up and down otherwise, never below the floor. B7: with the embedding model on disk (`memory_embed`), `blend_turn` blends the ask read with its 50 nearest labeled turns (`ask_set` plus learned ones in `models/ask_bank.json`: embeddings, kinds, lanes, rungs and outcomes, never text, `BANK_CAP` oldest-out); a thin bank keeps the rules (`knn:thin`), strong agreement wins, a split leans higher, a stakes turn only rises, and 18+ or banned turns never touch it.
- The accuracy guard (`guard.rs`): 10% holdout by FNV of the episode id, user-facing listed classes except `prepare:hard`, at fixed High (rule `holdout`, never in the reason). Hourly, per class with n >= 50 per arm, Auto more than 2 points below the holdout raises the class start and floor one rung (`models/route_overrides.json`) and tells no one: which effort a class starts at shows nowhere. Success is the Spike-7 outcome; a lane with no outcomes is judged on the learner's settled turns (`bandit::guard_stats`, holdout turns logged at p = 1 and never learned from). With neither it logs "guard waiting on outcomes" once a day.
- R2a model picking (`Router::pick_model`): only routes `spend::allowed` admits (no sign-in keeps the call's own model, `cost:not_included`; a key with no table row keeps it too, `key:keep`). One model per episode (sticky per episode key, class and turn); it changes only at a new user message, on `E15:next_model` (the strongest xAI model above the episode's, then the strongest provider model you set up, else it stays), or when the episode's model is unhealthy and a healthy one exists. D12: a typed chat past `SESSION_KEEP_TOKENS` (16k) keeps its model between turns (`pin:keep`), moves up whenever a turn needs a stronger model (`pin:upgrade`), and moves down only when `policy::pin_switch` finds the saving over `expected_remaining_turns` (at most `PIN_TURNS_CAP`) beats re-sending the history uncached (`pin:downgrade`). D13: `session_metrics.rs` keeps each chat's cache hit rate, model switches and escalation precision in `models/session_metrics.json` (`SESSION_METRICS_CAP` chats, counts and model ids only, never shown); `summary` is `TuneRun.sessions`. A pin is kept while it answers; otherwise its redirect successor, then its family newest first (`fallback_chain`), then the table. Nothing healthy pauses the call (`NO_ROUTE_MSG`, nothing sent, `take_no_route`). the breaker (`health.rs`): 3 hard failures in a row (5xx or a timeout) or one listed 404 quarantine a model; backoff 1m/5m/30m/2h/12h with full jitter, then one half-open check that shares the onboarding probe's daily cap. Retired and pruned rows are tombstones, deleted 30 days later (`Deleted` event).
- The routing table (`table.rs` + `capabilities.rs` + `attention.rs` + `feedback.rs`): Cheap/Workhorse/Code/Flagship baseline lanes (`baseline_score`); each turn escalates/de-escalates via built-in signals + learned bias (**no LLM**). `repair:diagnose` Flagship/ForceTop. Evals on `included` only. Heal in `heal.rs`; pin never rewritten.
- R2b cost classes (`cost_class.rs` `classify`, `spend.rs`, `budget.rs`): `included` (plan models; key models at or under the Settings price limit) goes freely. `autonomous_premium` (a `-fast` variant) only when `fast_verdict` finds you waiting live, a long chain or a time box at risk, never background/automation/proactive, only on a Grok Build sign-in (never a plain API key: the public API has no Fast variant), and the plain model when the week is at 80%. `premium` (over the price limit, priority, US endpoint, 16 agents) needs a `grant_premium` grant from the hard money card (`Step::Premium`); without it the step uses an included model (`cost:premium_ungranted`) and the cabin parks the card once. `extra_spend` has no code path and no URL. The week (`load_week`: `cost_in_usd_ticks` or prices × tokens; plan: 429 free-usage-exhausted) feeds DE3 at 80% (`budget_pct`); at 100% background pauses and chat asks (`BUDGET_ASK`); background stays under 15% of the cap. The cabin (`budget_ui.rs`) shows `EIGHTY_CARD` once a week and the upgrade nudge (`nudge_due`); `models/budget_notes.json` is cabin-written. Probes and evals use `probe_class` (plan only).
- R3a DE2 known routine (`ladder.rs` `routine_rung`, fed by `learn::routine_for` in `live::decide`): a task signature (`skill:<name>`, else the topic of the ask) with 3 successes at one lower rung within 14 days (and since its last failure) starts there. Never below the floor, never `prepare:hard`, never after a reject until VERIFY_OK, and "think hard" wins. R3a self-tuning (`tune.rs` pure, `learn.rs` I/O, hourly with the guard): scorecards per class, model and effort over 28 days (`models/scorecards.json`). The weekly pass (or a registry/profile change) proposes a class's first model or start rung. Cheaper/faster ones go shadow (200 steps, logged as `tune: shadow:<id>`) → canary (5% of eligible low-risk steps by episode: not `prepare:hard`, `repair:*`, holdout, a reject, a pin or a hard tool) → promote at n ≥ 50 when pass rate drops ≤ 2 pts, rework rises ≤ 2 pts and cost or p50 improves ≥ 10%, at most 2 a week. A drop within 7 days (n ≥ 30) rolls back at once and blocks it 14 days. Promotions and rollbacks write `{config}/route_tuning.json` through the ledger (kind `model`, id `route_tuning`, byte-identical Undo); `starts` merges over the class table (`Band::tuned`, clamped) and `orders` over the routing table at read time (`tune::tuned_table`), so `routing_table.json` stays R2a's and a rebuild can't drop a promotion. Anything that costs more also goes shadow, flagged, and promotes on its canary only with ≥ 5 pts more quality and a reward (quality − λ·cost) no lower than live; there is no card, line or Accept, and old router cards are dropped on load (`self_review::retired_card_source`). A shadow is judged on the learner's log first: with ≥ 20 matched turns its doubly-robust score must be within 0.02 of live (`bandit::ope`, IPS + DR), else it is rejected; after 14 days unjudged it goes to its canary. Per-user learner (`bandit.rs`): arms are model × effort from the registry (in-band rungs, eligible, `in_auto_pool`, pin switches only when `pin_switch` pays, xAI then one provider arm); Thompson sampling over reward per `lane|kind|difficulty` context with the read as prior steers ordinary chat turns through `Router::choose`; it explores up or sideways on 3% of low-stakes turns after 20 settled ones, never on hard, agentic, stakes, flagship, redo or attention turns, and never on the holdout, a canary, a sensitive, local or 18+ turn. Each turn settles on the next one (redo, tool trouble, a failed check, a code copy, cost) into `models/route_bandit.jsonl` (ids, contexts, probabilities and rewards only, 5000 lines) and `models/route_bandit.json`. The tuning and candidates stay in `route_tuning.json` and the tuner state, and show nowhere. The tuner refuses to run while the VerifyGate or outcome hook is a stub (`ready()`). R3a local model (`local.rs`): **Local route: off by default.** `app.json` `localModel` is false until Settings → Cabin defaults → "On-device model for background tasks" (`local_ai_ui.rs` `set_local_model`; the tick passes it to `local::set_enabled`, no restart). `local::enabled()` is the flag **and** `local::installed()`; `connectivity` (`Online`/`Degraded`/`Offline`) steers offline→local; `local::installed()` is a test fake or a llama-server binary + GGUF (`local_sidecar` / `local_http`: loopback-only, bearer token, health + restart, `chat_stream`). Env: `GROKHUB_LLAMA_SERVER` / `GROKHUB_LOCAL_MODEL`, else `{GROKHUB_CONFIG}/bin` + `models/*.gguf`. Without assets the toggle routes nothing; Set up opens the wizard on-device step (`app/setup_wizard.rs`). Wizard: GPU (`nvidia-smi`, else Linux DRM VRAM / Windows DXGI-CIM), RAM/disk (`detect_hardware`), `local::set_device`, `local_perf::apply_hardware` (ngl/threads/ctx/flash-attn/KV q8/idle unload + `local::set_ctx_cap`); hardware profile v2 (`local_profile.rs`: every GPU via `nvidia-smi` → DRM sysfs / Windows adapter registry → `vulkaninfo`, CPU P/E cores + SIMD, RAM, battery, thermal; probes in `app/local_probe.rs`, backend CUDA > ROCm > Metal > Vulkan > SYCL > CPU from the engine's `ggml-*` libs, dGPUs of one vendor split by free VRAM, iGPU left out) feeds `local_autoconfig::launch_for` (`gguf.rs` header → partial `-ngl`, MoE `--n-cpu-moe`, ctx/KV fit, threads from P-cores by `GovState`); `local_sidecar::start` logs to `bin/llama-server.log`, backs off 10% on out-of-memory up to 3 times, then names the next smaller catalog model, and keeps what ran in `{config}/local/autotune.json`; the live governor (`local_governor.rs` pure, readers and the 2 s / 5 s-on-battery sampler in `app/local_signals.rs`, applied by `route/local_gov.rs`) moves RampUp/Normal/Throttle/Unload with hysteresis (5 samples down, 30 up, no step up within 2 min of a change): fullscreen or a game (Windows notification state + full-monitor foreground + PDH GPU without the sidecar's pid; macOS games category; X11 `_NET_WM_STATE_FULLSCREEN`; Wayland Hyprland/Sway, then gamemode/gamescope/Steam/Proton/Wine, then another app over 60% GPU), low memory, hot or power saver Throttle; battery Throttles by default; battery under 20% or critical heat Unload (pauses the route); idle 5 min on AC RampUp, unknown idle never does; `{config}/local/governor.json` `allow`/`deny`/`throttleOnBattery`; no signals keeps load-on-demand; restarts only with no request in flight (`local_sidecar::busy`), a crash-loop breaker holds starts 30 min after 3 failures in 10 min; speculative decoding (`local_draft.rs` pairs and gates, `route/local_spec.rs` plan and speed test): the catalog `drafter` column pairs Gemma 4 E4B/12B/26B-A4B/31B with E2B, a GGUF with `nextn_predict_layers` drafts with its own MTP heads, and a non-catalog model takes any `models/drafters/*.gguf` with the same tokenizer hash (`gguf.rs`: SHA-256 of `tokenizer.ggml.model` + every token); the drafter is an offered download into `models/drafters/` that never replaces the installed model; `local_discover.rs` lists LM Studio / Ollama / user-folder GGUFs read-only, `local_setup::suggest` (the tier default from `local_picker::score` over `crates/grokhub-core/data/local_catalog.toml`: huihui-ai's abliterated Gemma 4 E2B/E4B/12B/26B-A4B/31B QAT Q4_K builds, SHA-pinned, with the banned-ask check (`adult_guard.rs`) in front of them like any model; Off, `LocalSource` lists nothing and `Router::choose` drops any `local:*` id. On (tests: `ForceOn`, or `Installed` plus the flag, with a fake `LocalRuntime`): `local:<tier>` is `included`, has no effort menu and a device context cap (`local::ctx_cap`, floor 4k, up to 8k–16k), takes only background classify/triage/redact/summarize while online (chat too while offline; never `prepare:hard` or a hard tool step), is the only route for sensitive data with no cloud grant, and writes no egress line; the downshift ladder only switches the live tier; PII is regex first, model second; `difficulty::estimate` uses it when on and R1's rules otherwise. R3b providers (`providers.rs`): **off until you add a key and allow the destination.** Settings → Cabin defaults "Add a provider" (https base URL, key into the OS keyring via `KeyVault`, never a file, span, ledger, log or model input); `models/providers.json` holds id, kind and URL only. OpenAI-compatible (`/models`, `/chat/completions`, effort `reasoning.effort`) or Anthropic (`/v1/models`, `/v1/messages`, effort `output_config.effort`); xAI's body is unchanged. Rows are `<provider>/<model>` (`SourceKind::OpenAiCompatible` / `Anthropic`), cost class `new_provider`, probe `not_run: cost_class`; the listing runs only with key and grant. Every request goes through `guard_provider` / `provider_or_park` (`Step::Provider` in `harness::decide`: your destination grant covering every class, chat alone is not enough, else a hard send card) and writes one egress line. A candidate only when `providers::usable` (key + grant covering the call's data; sensitive needs a grant naming it) puts it in `Spend.providers`, native call sites only (`RouteCall.providers`); taken by a table row, or by Auto's own pool (`provider:auto`) when it lists a price at or under the price ceiling and answers in text (ranked after xAI), or as the stand-in while xAI is down (`live::outage_stand_in`); never a cheapest pick or a tuner promotion. On OpenRouter Auto picks the model itself from the day's `/models` list (`LISTING_MAX_AGE_MS`), never `openrouter/auto`: `auto_pickable` wants `tools` on a tool step, `reasoning` on a reasoning lane, the context, a price under the ceiling, text out and no `expiration_date`. Each call sends `require_parameters` with `data_collection` deny by default, `models` as the pick and its backup (`openrouter_backup`), a hashed `session_id` and `reasoning.effort`. The stand-in ranks a provider busy or twice as slow lately (`lagging_providers`, latency EWMA `PROVIDER_EWMA_ALPHA`) after a healthy one. There is no user pin or pick: the router alone chooses. Permissions → Other providers: Allow parks the card (`ParkSource::Provider`), Revoke is one click. Saving a key is a hard credentials card first (`ParkSource::ProviderKey`, tool `model.provider_key`; the key waits in `ProviderUi::pending`, Approve calls `add_provider_as`, Deny/Esc/timeout drop it), then the send card. "Provider type" passes an API shape to `add_provider_as` for a proxy under another host (`None` detects from the host). "Get a key" opens `providers::key_page`; "Sign in with OpenRouter" runs `providers::openrouter_key` (PKCE S256 on the `loopback` redirect, code + verifier to `/api/v1/auth/keys` as a handshake send) and hands the key to the same credentials card. After a refresh `provider_refresh_note` counts the models a provider added (no names) or says it turned the key down (HTTP 401/403). Router + governor (`local.rs` `LocalCapacity`, `local_gov.rs`): `LocalGate.capacity` carries the governor level into `Router::choose`. Grok stays primary. Online, local takes background classes only in RampUp or Normal (`local:throttled` sends them to Grok under Throttle), and a heavy background step (over half the context cap) goes local only in RampUp (`local:heavy_waits`); `serve` holds a heavy step that still lands on the device (offline, cloud down) for RampUp up to `HEAVY_WAIT`. Offline and cloud-down work goes local at any level but Unload, where the step parks with `local:paused` and the chip "Local paused: game or low power" (no model-wait card). On-device route records carry `gov_state` and `tier`, and scorecards split by them. Settings → Local AI shows the state, level, tier, queue and log path (`local::status_lines`, painted by `ui_local_model_rows`). Level changes go to `{config}/local/governor.jsonl` (this device only, 7 days, deletable). Prompt tidy (`cleanup.rs`): `app.json` `promptCleanup` (off; Settings → Local AI, greyed out while Local AI is off, synced by `local::set_prompt_cleanup` next to `set_enabled`) lets `cleanup::tidy` send a typed chat ask to the already-loaded model (`local::warm_runtime`, never the router or the cloud) on one worker thread for at most `LIMIT` (300 ms, one call in flight); `keeps_meaning` drops any answer that changes a number, quote, path, URL, @-mention, a "not", a real word or the Brief's intent, care or domain, and `restore_typed` saves the typed text. Quota detection (`model_registry/quota.rs` pure state, `route/quota.rs` wire): OpenRouter `GET /api/v1/key` (FreeOnly / Paid / PaidLow / Negative; the free daily ceiling comes from `free_model_daily_requests.limit`, not `is_free_tier`), xAI `GET /v1/api-key` blocked flags, Anthropic from `anthropic-ratelimit-*` reply headers plus a local spend ledger priced off the registry table (cache writes at the prompt rate); checks ride the registry refresh (`RefreshJob.xai_bearer`), due every `QUOTA_POLL_MS` (10 min) or at once after a 402, 403 or 429 stamps `recheck_at_ms` (`providers::call_model` notes provider replies, `live::note_failure` native ones); Anthropic spend-limit 429 (`enforced_spend_limit_reached`, no Retry-After) benches to the 1st of next month, out-of-credit 400 for an hourly re-check; the scorer reads the ledger in a later step.

## Change recipe
- New model call site: send through `stream_routed` (native), `route::call_model` or `route::cabin::call_model` with its class. An internal site keeps its old effort by using a class whose start is that effort (`internal_call_sites_send_the_same_effort_as_before`).
- New class: add a `CLASS_TABLE` row (start / floor / ceiling) and a `plain` phrase for the reason.
- New listing field: parse it in `parse_model_row`, add it to `ModelMeta` with `#[serde(default)]`, keep unknown as `None`, and extend `merge_from`.
## What breaks it
- Treating 403 content-safety or 429 `free-usage-exhausted` as health (`content_safety_and_free_usage_change_nothing`), or counting an unlisted 404 as a ghost strike.
- Putting prompt text in a route record (`route_records_hold_no_prompt_text`), or a probe prompt built from user data (`probe_prompts_contain_no_user_data`).
- A new `ureq` builder in `sources.rs` without its `WRAPPED` count in `crates/grokhub-agent/src/harness/egress_coverage.rs`.
## What depends on it
- R3a fills DE2 and joins route records with `outcomes.jsonl` by episode. R3b's `new_provider` routes ride the same `Spend` and `harness::decide`.
## Non-obvious
- `harness::decide` stays the only approval gate: the router picks how to think, never whether to act. A GB-only model gets a metadata-only profile (`not_run: gb_only`); a queued probe is not usable yet.
- `PROVIDER_GROK_BUILD` (`grok_build`) is left from the CLI path: a call logged under it gets no outcome and no health (`crates/grokhub-agent/src/route/live.rs`). No CLI turn runs now; chat, background, and scheduled turns are native.
- The ladder's state is in memory per episode and class; tool errors and the A4/E14 stage signals reach it through thread-locals (`note_tool_error`, `take_stage`), so the next routed call on the same thread reads them.
