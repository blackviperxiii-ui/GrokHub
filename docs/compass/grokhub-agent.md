# Compass: grokhub-agent (native Lab engine)

## Owns
- The native xAI Responses engine: sync HTTP client, agent loop, tools, permission gate and rule engine, MCP client, hooks, skills, plugins, subagents, memory, sessions, unattended runs, and the dry-run eval.
- It is the only engine: every chat, background, and scheduled turn runs here; nothing launches the Grok Build CLI.
## Quick commands
- `cargo test -p grokhub-agent --locked -- --test-threads=1`
- `cargo test -p grokhub-agent --test mcp_transport` (spawns the `fake_mcp` bin)
- `cargo run -p grokhub-agent --example eval` (dry-run; `--live` is refused)
## Key files
- `crates/grokhub-agent/src/lib.rs`: module list and the public surface the app uses.
- `crates/grokhub-agent/src/run.rs` (`run_loop`) and `crates/grokhub-agent/src/events.rs` (loop events to the `AcpEvent`s the cabin polls in `poll_acp`). Before the loop, `crates/grokhub-agent/src/brain/instant.rs` answers a plain read-only ask ("list my skills", "how much disk space do I have") from one tool and a fixed reply with no model call, only when the Brief is a sure question or task and the gate and PreToolUse hooks say Run; anything else falls through.
- `crates/grokhub-agent/src/gate.rs` (gate v0) and `crates/grokhub-agent/src/perm/mod.rs` (rule engine).
- `crates/grokhub-agent/src/tools/mod.rs`: `tool_schemas`, `schemas_for`, `schemas_for_job` / `ToolSet` (per-job allowlist filter), `execute` (read-only), `dispatch` / `dispatch_for_job` (gated set; job set refuses with `tool_set_outside`). `tools/talk.rs` (LO-45): a chat whose first Brief is plain talk keeps `TALK_DEMOTED` in the deferred index until a work Brief or one load of them appends them all; it shapes the list only, never dispatch or the gate.
- `crates/grokhub-agent/src/tools/fence.rs`, `crates/grokhub-agent/src/file_checkpoint.rs`, `crates/grokhub-agent/src/recovery.rs`: fences; copy-before-write (`/rewind step`; Brain 2 `checkpoint.rs` = gaps); `RecoveryState` projects ladder/parks/drive (no second retry stack).
## Change recipe
- New tool: add a module under `crates/grokhub-agent/src/tools/`, register its schema in `schemas_for` on the right side of the `readonly_session` / `desktop` checks, dispatch it, and make sure `gate::decide` and the harness see it. Cabin `web_search` (`tools/web_search.rs`) is the free OpenRouter/local path; xAI hosted search strips that function tool in `responses_body` when `hosted_search` is on.
- Outside data returned to the model: wrap with `tools::fence::fence(source, text)` (or `fence_if_outside` for path-gated reads).
- Ported code: keep the `// Portions derived from xai-org/grok-build ...` header and add a line to `crates/grokhub-agent/NOTICE`.
## What breaks it
- Loosening a deny: perm rules are deny > ask > allow; hooks can deny or ask but never turn a gate deny or ask into allow; a hook timeout is no decision.
- Reading the Grok CLI's credentials (`~/.grok/auth.json`): the engine uses GrokHub's own sign-in (`XAI_NEED_SIGNIN` in `crates/grokhub-core/src/xai_signin.rs`).
## What depends on it
- grokhub-app: `crates/grokhub-app/src/app/native_engine.rs`, `crates/grokhub-app/src/app/native_sessions.rs`, `crates/grokhub-app/src/app/native_unattended.rs`, `crates/grokhub-app/src/native_mcp.rs`, `crates/grokhub-app/src/native_plugins.rs`, plus the harness and `ToolOutput` in the desktop MCP.
## Non-obvious
- Gate v0 still treats Auto like Ask; Plan and btw stay read-only (`READ_ONLY_PHASE`).
- Unattended runs (`run_unattended`): Ask denies every non-read-only tool; Auto uses the Phase 5 judge and fails closed.
- Subagents: Explore is read-only, General copies the parent gate, depth 2 stops grandchildren, a worktree never falls back to the parent tree.
- `system_prompt_parts` / `system_prompt_with` (`prompt.rs`) and optional `prefix_cache.rs` (`{config}/prefix_cache.toml`, off by default): cache-friendly stable prefix (cabin + AGENTS/skills) then volatile tail; when prefix cache is on, per-turn style/playbook/memory ride in `<cabin-volatile>` on the user message instead of rewriting the system row. Open intentions from `crates/grokhub-core/src/goal.rs` ride that tail, and `close_check.rs` makes one low-effort call before a depth-0 `EndTurn` when an intention is open or waiting, or plan mode still has a pending todo. `prompt_need_from_job` / `tool_set_from_job` parse `NEED_*` / `TOOLS:` tokens from a job brief; SP2 wires background and unattended callers.
- Optional `show_panel` native tool (`tools/show_panel.rs`, `generative_ui.toml` off by default): validates a panel spec as tool output; the cabin drains and paints it (G4).
- Auto-compact (`compact.rs` / `run.rs`): re-arms after a new turn; context-length errors compact once and retry, then stop with `context still too large after compaction`. An xAI model on api.x.ai compacts on xAI's side first (`/v1/responses/compact` via `route::live::compact_routed`, capped at `SERVER_COMPACT_TIMEOUT`): the old part becomes opaque `InputItem::ServerCompaction` items (kept byte for byte, saved as `server_compaction` session lines), the recent tail stays verbatim; any endpoint error falls back to the summary. `{config}/compaction.toml` `backend = "summary"` turns it off. Providers and local models skip those items. History trim (`compact::trim_pass` from `run.rs`, before the auto-compact check): at 40% of the window or more, an older `read_file` / `list_dir` / `grep` / `glob` output whose call a later call repeats with the same arguments becomes a one-line `[Output dropped: …]` note naming that later call (`trim_history`), but only when the later call succeeded: `run.rs` `push_output` records each non-failed `ToolOutput` with `compact::note_tool_result`, so an errored, refused or (after a restart) unknown later call never drops anything; every call/output pair stays and messages are never touched. At most one pass changes the history per turn and `prefix_guard::note_trim` names the cache break `trim`. `{config}/history_trim.toml`: `enabled = false` turns it off; `age_out = true` (off by default) spools outputs of `age_out_min_bytes` (12,000) or more with `age_out_user_turns` (3) user turns after them, as an extractive summary plus handle (`age_out_history`).
- `crates/grokhub-agent/src/memory.rs` keeps `MEMORY.md` plus a rebuildable `index.sqlite`. `crates/grokhub-agent/src/identity.rs` reads SOUL.md and USER.md into the volatile tail (redacted, capped at `SOUL_BYTE_CAP` and `USER_BYTE_CAP`); `memory.rs` still does not write those files. `crates/grokhub-agent/src/dream_model.rs` (`sleep_dream`) proposes USER and SOUL lines when `dream_model_enabled` is on. Recall (`first_turn_injection` / `followup_injection`) goes through `redact_recall`, and a later turn injects only new hits. `recall_token_cap` in app.json overrides the 1,024-token cap. A missing app.json means AMR; an omitted `memory_backend` stays legacy. Gaming asks still inject sealed `scope:apps` lines from `ScopeIndex`. Cabin skills live under `{config}/skills` and are discovered by `skills::discover` (source `cabin`) so `skill_list` and `skill` share ids. Built-in vstack skills (`assets/skills/`, source `builtin`: qa-walkthrough, av-qa-walkthrough, create-/maintain-verification-skill, follow-through) ship with the app; project/user/cabin/plugin same-name wins. `plan_skills.rs` wires ship→QA (+AV when needed), verify-before-done, and multi-step→follow-through into the skills reminder, close-check, playbooks, and the run-loop prompt.
- MCP protocol (`crates/grokhub-agent/src/mcp/rpc.rs`): connect probes `server/discover` first and `pick_era` reads the answer: a `DiscoverResult` or a reserved modern error (-32020..-32022) means stateless 2026-07-28 (`with_meta` on every request, no `initialize` or `Mcp-Session-Id`, `ping` becomes `server/discover`, `call_tool` answers `input_required` on the elicit card with `requestState`; HTTP adds `Mcp-Method`, `Mcp-Name` and `x-mcp-header` params from `crates/grokhub-agent/src/mcp/headers.rs`); anything else falls back to `initialize` with `LATEST` (2025-11-25), `negotiate` over `SESSION_VERSIONS`, and the version header after it. Stdio sends `initialize` after `PROBE_WAIT` (2 s) but a late discover answer still wins; a 401 or 403 on the HTTP probe stays a sign-in error. `tool_output` adds `structuredContent` and `resource_link` lines inside the `mcp` fence. A tool with `destructiveHint: true` asks under Always, refuses unattended, and skips the auto-review judge (`decide_mcp`); only the user's own allow rule runs it without a card. Browser sign-in (`crates/grokhub-agent/src/mcp/oauth.rs`, pure parts in `crates/grokhub-core/src/mcp_oauth.rs`, PKCE in `crates/grokhub-core/src/pkce.rs`): a remote server with no `Authorization` on its entry signs in from its Native MCP row. The sign-in is sealed by `seal_mcp_signin` (keyring key, next to the connection tokens), refreshed a minute before expiry, and refreshed once on a 401 before the row asks for a new sign-in. An entry that carries its own header or `tokenRef` never uses it. `file_checkpoint::before_write` hooks `write` / `search_replace` only; `run.rs` calls `begin_step` per tool batch; store `<config>/checkpoints/<conversation>/<step>/`.
