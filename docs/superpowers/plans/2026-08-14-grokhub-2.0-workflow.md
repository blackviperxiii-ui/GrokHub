# GrokHub 2.0 workflow

> Operating system for shipping every pinned recommendation (Waves 1–6) plus 2.0 thrusts A+B+C.
> Spec: `docs/superpowers/specs/2026-08-14-competitor-takeaways-design.md`
> Tasks: `docs/superpowers/plans/2026-08-14-grokhub-2.0-implementation.md`

**Product sentence:** You sit down in the cabin. It already knows the night. It sees you. You see it think. You say Hey Grok without opening anything. When you leave, it keeps driving. When you sit at another box, the same Grok is there.

**Required execution skill:** `superpowers:subagent-driven-development` (one fresh subagent per task, review between tasks). Fallback: `superpowers:executing-plans` in this session.

---

## Rules (every task inherits these)

1. **Don’t add features. Add skills** — except **Presence** (Wave 5: organs) and **Cabin** (Wave 6: the being). Presence = live room, Grok Voice, rewind. Cabin = windshield, cabin eyes, Hey Grok, mid-thought, speak-the-room, third body, passenger. Still no Telegram/Discord, no provider zoo, no WASM, no hook YAML, no multi-agent OS, no Tesla vehicle API, no waifu.
2. **Trunk stays:** chat, host, memory, skills, automations, Imagine, Devices, workboard, autonomy.
3. **Files over databases** for memory/skills (`MEMORY.md`, `USER.md`, `SOUL.md`, `skills/<id>/SKILL.md`).
4. **Supervised is the default story.** YOLO is a named escape hatch for `/approve off`.
5. **One writer per thread** (session lock). Composer can still type; Imagine can still run.
6. **Test first** with `scripts/smoke-*.mjs` (Node strip-types, no network) plus `npm run typecheck` at phase end.
7. **Commit per task.** Phase end = push + update the 2.0 PR. Do not batch unrelated phases.
8. **Do not rebuild** anything in the spec’s “Already in GrokHub” list. Extend it.

---

## How to pick up work

1. Open the implementation plan. Find the first unchecked `- [ ]` task in the **current phase**.
2. Do not start Phase N+1 until Phase N’s **phase gate** is green.
3. Dispatch a subagent with: spec path, this workflow, the single task block, and “touch only listed files.”
4. Review the diff against the spec item IDs in that task (`W1-…` … `W6-…`, `A/B/C`).
5. Check the boxes in the plan file in the same commit as the code, or in a follow-up `docs: check off Task N` commit.
6. If blocked, write `BLOCKED: reason` under the task and stop that slice — continue only if a later task does not depend on it.

## Done when

A stranger can:

1. Run a messy desktop task once; the second time is a skill (chip + `SKILL.md`).
2. Send that task from another paired device; this box does it.
3. Open the receipt and the `SKILL.md`.
4. Leave a script-gated automation overnight without a surprise destructive host run.
5. From another device, watch it click and say “stop, other window” — it steers.
6. Rewind last job; the project folder goes back.
7. Sit down to a mid-thought cabin (greet / dream film / pinned goal) — not a fresh chat.
8. Say Hey Grok without focusing the app; watch the windshield (objects + next click + a won’t).
9. Restage the room with one sentence, or show the camera an object it can act on.
10. Hand the same Grok to another paired Linux box; phone stays the key fob.

**2.0.0 bar:** phases 1–2, 7, 9, and **10.1 + 10.3 + 10.4 + 10.7** green. 10.2 / 10.5 / 10.6 may ship in the same release if they do not slip the headline demo; they are full-bloat encore, not optional philosophy. Version bump is a dedicated release task (not mixed into feature commits).
