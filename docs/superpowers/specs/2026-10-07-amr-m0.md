# AMR M0 — 2026-10-07

Schema, an empty local store, and a flag-gated `/recall` read. Default stays legacy. No version bump.

## Layout

`{config}/amr/` (`app.json` lives in the same config dir): `README.md` (`amr_schema: 1`), `nodes/<id>.md`, `edges/edges.jsonl`, `dreams/` (unused). Node frontmatter is `id`, `type`, `created`, `updated`, `source`, `confidence`, `tags`, then a markdown body. Types: preference, fact, decision, trail, person, project. Edges: references, supersedes, learned_from_span, about_project, contradicts.

Ids are `[a-z0-9-]`, 1..=96, not starting with `-`. Confidence outside 0.0–1.0 is an error. Writes run body, source, and tags through `redact_secrets`.

## Flag

`memory_backend` on `AppConfig`, JSON key `"memory_backend"` in `app.json` (`"legacy"` default, `"amr"` opt-in). The key is omitted when legacy, so old files and a default save stay unchanged. No Settings control.

`/recall` with legacy is the existing SOUL/USER/MEMORY/learned path plus thread rows. With `amr`, memory hits come from `AmrStore` (init on that path only) and thread rows are still searched. Legacy never creates `amr/`.

## Not in M0

No migration or import of MEMORY.md, LearningState, or Pulse lines. No dream, no default writes from `/learn`, `/memory`, or reflect. No `forget`. No hub sync of `amr/`. No Leviathan, Mem0, or Hindsight. No consent UI, encryption, or new page. `harness::decide` and the approval gate are untouched.
