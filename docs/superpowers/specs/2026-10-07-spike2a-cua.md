# Spike-2a: Cua Driver as a second pair of hands (Linux)

Status: built behind the `cuaDriver` spike flag (off by default). The live Linux run and the measurement below are **not done yet**: they need a Linux desktop session with the pinned `cua-driver` installed and a signed-in Grok Build, which the cloud build box does not have.

## What ships

- `ComputerUseBackend::CuaDriver` beside `GrokBuild` (`crates/grokhub-agent/src/harness/backend.rs`). `ComputerUseBackend::selected` returns Cua only when `app.json` has `"cuaDriver": true`, desktop control is on, and the OS is Linux. The key is omitted from `app.json` while false. No Settings control.
- Pinned binary (`crates/grokhub-agent/src/harness/cua.rs`): `cua-driver` from `cuaDriverPath` in `app.json` or PATH. `cua-driver --version` must report exactly the pinned version and must not mention the AGPL perception extension, or the proxy refuses in plain words.
- `grokhub --mcp-cua`: a cabin MCP server registered as `grokhub-cua` in the cabin `GROK_HOME` (never `~/.grok`) only while desktop control and the flag are both on. It starts `cua-driver mcp --socket <config>/cua/driver.sock` as its own child with `CUA_DRIVER_PERMISSION_MODE=bounded`, `CUA_DRIVER_CAPABILITY_MANIFEST_FILE=<config>/cua/manifest.yaml`, and `CUA_DRIVER_CAPABILITY_MANIFEST_APPROVED=1`, and strips `CUA_DRIVER_DANGEROUSLY_BYPASS_APPROVALS` and `CUA_DRIVER_POLICY_FILE`. Grok Build only talks to the proxy over stdio and never sees the socket.
- Every `tools/call` goes through `harness::decide` before it is forwarded. Cua names are read as the desk tool they match (`cua_as_desk`: `type_text`/`set_value` as `type`, `press_key`/`hotkey` as `key`, `launch_app` as `open_app`). The floor refuses, hard class parks the path A card (`park_desk_call`), toggle or flag off refuses, and a tool outside the manifest refuses. Halt kills the child and denies every park; nothing is forwarded after it.
- After a click the proxy observes again (`get_window_state` first, `screenshot` as fallback) and records `ui_changed`, so an unchanged UI becomes a silent-fail span that Spike-1a's ladder picks up.
- `%password%`: the model only ever sees the slot. A slot parks as hard class credentials; with no credential store in the cabin yet, Approve still types nothing and says so.
- Spans: path `A`, `driver:"cua"`, the Cua tool name in the claim, typed text stored as its length only.
- `grokhub-cua` is denied wherever `grokhub-desktop` is (`--deny MCPTool(grokhub-cua__*)`: desktop off, Plan, unattended Ask) and is never allowed by a rule.
- Live view: the agent cursor marker on the Work-tree frame maps Cua's six cursor motions (`signature_arc` default, `spring_settle`, `magnetic`, `comet_swoop`, `adaptive`, `classic`) onto `motion::AgentCursorAnim` (`grokhub_core::cursor_motion`). The style is the constant `AGENT_CURSOR_MOTION`. Reduced motion snaps on the first frame.

## Manifest (`cua_manifest`)

```yaml
version: 1
mode: bounded
resources:
  applications:
    - bundle_id: org.gnome.TextEditor
    - bundle_id: org.gnome.gedit
    - bundle_id: org.kde.kate
    - bundle_id: org.kde.kwrite
    - bundle_id: org.xfce.mousepad
allow:
  tools:
    - start_session
    - end_session
    - list_apps
    - list_windows
    - launch_app
    - get_window_state
    - screenshot
    - click
    - type_text
    - set_value
    - press_key
    - hotkey
    - scroll
    - drag
    - wait
deny:
  tools:
    - shell_execute
    - page
    - browser_download
    - browser_set_input_files
```

The manifest schema follows Cua's driver permission-modes plan; it has not been checked against a live 0.34.0 driver yet.

## Measurement (Alan's-way hypothesis)

Task, fixed: open a disposable text editor window, type one line, save it to a temp dir. Five runs per path.

| Path | Median wall time per step (open / type / save) | Screenshots per task | Tokens in / cached / out / reasoning per task | Successes |
|---|---|---|---|---|
| GB → `grokhub-desktop` (screenshot) | not measured | not measured | not measured | not measured |
| GB → `grokhub-cua` (AX-first) | not measured | not measured | not measured | not measured |

No Spike-1W numbers exist to compare against yet (Spike-1W's live Surface run is still to do).

How to run it on a Linux desktop: install the pinned release, set `"cuaDriver": true` in `app.json`, turn on desktop control, start one chat per path with the task above, and read each turn's spans (`spans/<chat>.jsonl`: one span per step with `driver`, `ts_ms`) and the turn's usage line for tokens.

## Router-ready

This spike adds and touches no model calls (the proxy only relays Grok Build's tool calls), so no `ModelCall` wrapper was added; a wrapper with no caller would be dead code. Effort and model routing stays for the step that first adds a cabin-side model call.

## Not in this spike (Spike-2b)

Click-target classification, tool search, and a cabin-side batch runner (Grok Build sends one tool call at a time, so the proxy gates each one).
