# AMR M1–M2 — 2026-10-07

New remembers go into the agent memory repo, reads see both stores, `forget` is a tombstone, and what GrokHub already learned is imported once. Everything here runs only with `"memory_backend": "amr"` in `app.json`. Legacy is untouched and never creates `amr/`. No version bump, no Settings control, no model calls.

## M1: single write, dual read

Writers moved (each writes one node through `AmrStore::remember` instead of a MEMORY.md, USER.md or learning.json line):

- reflect (`run_reflect` → `run_reflect_amr`), tag `reflect`, `source: chat:<thread_id>`, confidence 0.7
- chat insights (`absorb_turn_learning`, the `extract_insights` / `upsert_insight` write), tag `insight`, confidence 0.7
- `/memory note`, `/remember`, `/mem <note>`, tag `note`, confidence 1.0
- Memory Save on the MEMORY.md tab: lines new against the file become nodes (tag `memory-save`) and leave the editor; edits to existing lines still save to the file
- native `/remember`, tag `native` (the `--global` / `global:` prefix is dropped; the repo has one scope)

Node ids are `mem-<12 hex>` of the normalized, redacted line, so one line is one node. Personal lines (email, phone, card, SSN, address) are sealed; with no key the write is `Paused` and nothing lands anywhere. Held secrets are masked before the write and `redact_secrets` runs in the store. Scratch writes nothing.

Not moved: SOUL.md and USER.md (curated), the Pulse ledger lines, chip habit lessons and engine part notes (rebuilt state, not memory), `/import`, `/dream`, and the Memory editor's autosave on navigation.

Dual read: `/recall` returns AMR lines first, then SOUL/USER/MEMORY and chip habit lines, with lines of identical text once. History lists AMR hits (`amr:<id>`) before the legacy files and chats. The native first-turn pack adds AMR hits for the message's words, deduped, through `redact_recall`.

## Forget

`MemoryEngine::forget(id)` writes `nodes/<id>.tombstone`; the node file stays. Recall, History, the first-turn pack and the import skip it. `/forget <topic>` in AMR mode tombstones every match, says how many, and still drops the topic from MEMORY.md. Scratch blocks it. No agent-made forget.

## M2: import

On the first AMR read or write of a session (outside scratch), `import_legacy` copies:

- `LearningState.insights` as `preference` (key `pref…` or a preference-shaped line) or `fact`, `source: learning_state`. `habit:` and `skip:` lines are skipped: chips rebuild them.
- `ChipMemory`: `last_slash`, `last_surface`, and chips picked from the row at least twice and never dismissed (label only), as `preference`, `source: chips`. Left out: hit values (can hold typed text), counters, hour histograms, transitions, `last_chip_key`, `total_events`, timestamps.

Ids are `import-<12 hex>` of source and key; a rerun writes 0 nodes. Legacy files are only read. When something was imported, `dreams/import-<date>.md` gets the counts per source with skip reasons, and the chat gets one line: `Memory import: N imported, M skipped (learning_state A, chips B).`
